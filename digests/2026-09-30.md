## ⚠️ 今の使い方が変わるもの

**① 成果物の「常に許可」の効く範囲が変わりました**
成果物ツールに対して「今後聞かないで」を選んでいた場合、
**作業フォルダの外にあるファイルも、確認なしで公開できて**いました。
今回から、**そのルールは作業フォルダの中だけに効きます**。
外のファイルを扱いたい場合は、`--add-dir` でそのフォルダを追加してください。

**② `WebFetch`（Web ページの取得）を止める設定が追加されました**
`CLAUDE_CODE_DISABLE_WEB_FETCH` を設定すると、Web ページを取ってくる機能を無効にできます。

**③ 組織側で、使える接続先を限定できるようになりました**
`allowedProviders` で、その機械が使ってよい接続先（Anthropic の API、独自の窓口、
第三者クラウドなど）を絞れます。※ 個人利用なら関係ありません。

## 今日の変更（説明つき）

### 成果物（Artifact）まわりが10件直りました

今日いちばん手が入った部分です。**元のファイルを壊す危険があったもの**が中心です。

- **会話を巻き戻したあとに公開すると、元ファイルの新しい内容を上書き**していた
  → 今は、読み直すまで公開を拒否します
- **読み取りが途中で切れていた／ファイルが変わっていた場合も、上書きできて**いた
  → 同じく読み直しを要求します
- **`/artifacts` の一覧で行を消すと、ファイルと成果物の結び付きが切れて**いた
  → 同じファイルを公開し直すと別の成果物が作られていました
- 一時的なサーバーエラーの再試行で、**成功していたのに「衝突」と報告**されていた
- 圧縮のあと再起動したクラウドセッションが、**自分が公開した成果物を更新できなく**なっていた
- auto モードの安全判定が、**一部の操作で飛ばされて**いた
- 「常に許可」の範囲の件（上記 ⚠️①）

*気になるなら聞けること: 「成果物って、うちの運用でどこかに使ってた?」*

### Remote Control で、添付と未読の扱いが直りました

- **添付ファイルの取得が1回失敗すると、そのまま落ちて**いました
  → 今は最大2回やり直します
- **メッセージを受け取った時点で「既読」にしていた**
  → 今は Claude が着手した時点になります
- **端末を終了すると、順番待ちのメッセージが失われて**いました
  → 今は次に再開したときに届きます

*気になるなら聞けること: 「スマホから送ったのに届いてなかったこと、ある?」*

### 記録に、パスワードが一部残っていました

記録やログでパスワードを隠す処理が、**`@` を含むパスワードだと一部が見えて**いました。
さらに、URL の中で `@` を `%40` と書いている場合は**全部見えて**いました。今回直っています。

### `ANTHROPIC_AUTH_TOKEN` を使うと、組織の設定が読まれていませんでした

その方式で Anthropic の API に認証しているセッションは、
**組織の方針が一度も読み込まれない**状態でした。今回直っています。

### 止めたはずのコマンドが、最後まで走っていました

コマンドや確認処理を**準備している最中に中止**すると、
**それでも起動して最後まで実行されて**いました。今回直っています。

### 確認処理が、裏のプロセスのせいで固まっていました

確認処理（フック）の中で `some-daemon &` のように**裏で動くものを起動**すると、
**その出力が開いたままなので Claude Code 全体が待ち続けて**いました。
今回から、確認処理そのものが終わればすぐ次に進みます。
