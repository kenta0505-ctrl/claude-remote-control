## ② ⚠️ 今の使い方が変わるもの

### Opus 4.7 以降と Fable が、既定で100万トークンのコンテキストウィンドウに

- コンテキストウィンドウ = 一度に扱える文章量の上限です。
- 対象は **Amazon Bedrock / Google Vertex / Microsoft Foundry / Claude アプリ用ゲートウェイ** 経由で使う場合。これまで必要だったモデル名の `[1m]` という接尾辞が不要になりました。
- 200万…ではなく **20万 → 100万** です。5倍に増えます。
- 元に戻したい場合は環境変数 `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` で 20万に固定できます。

**原さんへの関係**: 原さんは claude.ai とアプリ経由（Claude Opus 5）なので、上記4つの経路のどれにも当たりません。**直接の影響はありません。** ただ「100万トークンが既定になる流れ」自体は、長い会話や大きな資料を扱うときの前提が変わる話です。

### Mods は「あなたの権限で動くコード」です

次項で説明する Mods について、ドキュメントに明示されている注意です。入れる前に知っておく必要がある種類の話なので、⚠️ に置きます。

Mod を入れると、それは **原さんのパソコンの権限そのままで動くプログラム** になります。公式ドキュメントが挙げている「Mod ができること」は以下です。

- ファイルの読み書き、プログラムの起動、ネットワーク通信（原さんのユーザー権限の範囲すべて）
- 環境変数や設定ファイルの読み取り（そこに置いた APIキーを含む）
- 送ったプロンプトと Claude のツール呼び出しをすべて見る
- プロンプトやツール呼び出しを書き換える、入力したかのようにプロンプトを送る、別のセッションにメッセージを送る
- **確認を求められる前にツール呼び出しを承認してしまう**（`ask` ルールや自前の `PreToolUse` フックで止めていたものを含む）
- 原さんのプランやAPIキーでモデルを呼ぶ（使用量を消費する）

一方で **できないこと**も明記されています。Mod は Claude Code の画面の大部分を書き換えられますが、**許可を求めるプロンプト（permission prompt）だけは書き換えられません**。そこに表示される内容は変えられない設計です。

公式の言い方は「信頼できる作者とマーケットプレイスからのみインストールしてください」です。

## ③ 今日の変更（説明つき）

### Claude Mods — プラグインが Claude Code 自体を書き換えられるようになりました

Mod は **プラグイン（Claude Code の拡張機能）の一種**で、中身は JavaScript または TypeScript の関数です。ツール呼び出し・プロンプト送信・画面の描画といった出来事が起きたときに Claude Code がその関数を呼び、関数は **見ているだけ・書き換える・乗っ取る** のいずれもできます。

これまでの拡張手段（設定ファイルのフック、スキル、MCP サーバー）はすべて **Claude Code の外側**で動いていました。Mod は **内側**で動くので、外側からはできないことができます。

- 記録の横に出るパネルや、入力欄の上に出る帯を描く（タブ・ボタン・入力欄付き）
- Claude Code 自身が描いている部分を差し替える（ツール呼び出しの行、ぐるぐる回る表示、Claude が質問するダイアログなど）
- ツール呼び出しや API リクエストの途中に割り込む（ツールを止めて利用者に質問する、ツールを実行せずに答えを返す、1つのリクエストだけ別のモデルに送る、など）
- Claude のターンを待たずに即座に自分のコードを実行する `/コマンド` を追加する（Claude が作業中でも動く）
- 複数のフックで変数を共有する（片方がトークン使用量を記録し、もう片方がパネルに図を描く、など）

動くのは **Claude Code の CLI（ターミナル）と Claude デスクトップアプリの Code タブ**です。VSCode 拡張、`claude -p`、クラウドセッションでの挙動は別途ドキュメントに記載があります。

入れ方は普通のプラグインと同じで、`/plugin install <名前>@<マーケットプレイス名>` です。すでに Claude Code の機能のいくつかは Mod として作られています（`/diff` など）。自分で書かずに **「こういうものが欲しい」と Claude Code に伝えて書かせる**こともできる、と公式に書かれています。

### 「You should know」— 横で見ていて見落としを指摘してくれる内蔵 Mod

Mods と同時に入った、Anthropic 製の内蔵 Mod です。**脇に控えたエージェント（作業係）が会話を見ていて、原さんや Claude が見落としそうなことを指摘します。**

有効化は `/plugin enable cc-plugin-you-should-know@builtin` です。ただし **「テレメトリ（利用状況の送信）が有効な first-party セッション向け」** という条件が CHANGELOG に明記されています。

気になるなら聞けること: 「テレメトリが有効かどうかって、どこを見れば分かる?」

### 危険な `rm` の「必ず確認する」保護が外れていた不具合

`/`（ルート）やホームディレクトリに対する `rm`（削除コマンド）のような危険なものは、必ず確認を求める仕組みになっています。ところが **同じコマンドが `~` やワイルドカードを使った出力リダイレクトも含んでいると、この保護が外れていました。**

実際に消える側の事故なので、今日の修正の中では一番重い部類です。

### MCP ツールが `__proto__` という名前だと、組織の権限上限が無言で無効になっていた

組織が「このツールにはここまでしか許可しない」と決めた上限（per-tool permission ceiling）が、**ツール名が `__proto__` の場合だけ黙って無視されていました。** JavaScript の内部的な特別名と衝突する種類の不具合です。

組織で権限制限をかけている場合、その制限が効いていなかったことになります。

### コネクタのツール呼び出しが2回走る／再起動まで失敗し続ける不具合

Square や Gmail のようなコネクタ（MCP 接続）で、相手サーバーが **対応する MCP プロトコルのバージョンを変えた**ときに、ツール呼び出しが **2回実行される**ことがあり、あるいは **Claude Code を再起動するまでそのコネクタの呼び出しが全部失敗する**ことがありました。

「2回実行される」のは、書き込み系の操作だと二重登録などにつながる種類の不具合です（原さんの Square 接続は読み取り専用の取り決めなので、そちら側では無害です）。

気になるなら聞けること: 「Gmail の下書きが2通できてた日とかある?」

### クラウドセッションが、圧縮中の再起動で前半の会話を失う不具合

claude.ai/code のセッションが、**会話を圧縮（compaction、長い会話を要約して縮める処理）している最中に再起動すると、それより前の会話が消える**ことがありました。これが直りました。

この digest セッションは実際に9月末に中身を失っているので（あのときは容量不足によるコンテナ入れ替えで、原因は別です）、同じ「長く続くセッションが中身を落とす」系統の修正です。

### MCP サーバーがサインイン用の URL を出せるようになりました

2025-11-25 版のプロトコルに対応した MCP サーバーが、**URL を提示するプロンプト**（たとえばサインイン用のリンク）を出せるようになりました。

**この更新後に繋がらなくなったサーバーがある場合**、その MCP 設定に `"bareElicitationCapability": true` を追加する、と CHANGELOG に対処法が書かれています。

### `/model` で Fable を選んだときの保存の仕方が直りました

claude.ai のログインで `/model` から Fable を選ぶと、**その時点のバージョンのIDが保存されていました**。つまり新しい Fable が出ても古い方に固定されたままでした。今は Opus や Sonnet と同じように、保存した既定が最新の Fable を追いかけます。

あわせて、**Opus 5.5 と Sonnet 5.5 を `/model` や `opusplan` で切り替えると、それ以前の MCP ツールの案内が書き換わり、以前の拡張思考（extended thinking、モデルが長く考えた記録）が消えることがあった**のも修正されました。

### Admin API が beta から正式版になりました

組織の管理（メンバー、招待、ワークスペース、APIキー、レート上限、サービスアカウント、暗号化キーなど）を API から操作する **Admin API** のドキュメントURLが `api/beta/organization/...` から `api/organization/...` に移りました。

あわせてドキュメント側で、分析系のエンドポイント名が整理されています（`cost` → `cost_report`、`usage` → `usage_report`、ユーザー別は `user_cost_report` / `user_usage_report` など）。原さんが使う範囲ではありませんが、間引かずに記録しておきます。

### プラグインを組織で配る API が追加されました（beta）

`api/beta/organization/plugins/...` と `plugin_marketplaces/...` が新設されました。組織としてプラグイン（Mod を含む）を作成・配布・バージョン管理し、どのメンバーにどう入れるかを設定するための API です。管理画面側の `manage-claude/plugins-api` ページも追加されています。
