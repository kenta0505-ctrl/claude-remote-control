## ③ 今日の変更（説明つき）

### 危険な `rm` の確認が外れる穴が、もう1つ見つかって直りました

昨日お伝えしたのと同じ系統の、しかし別の経路の穴です。

`/`（ルート）やホームディレクトリに対する `rm`（削除コマンド）は、必ず確認を求める仕組みになっています。今回直ったのは、**その `rm` が `bash -c` や `sh -c` の中のスクリプトに書かれていた場合**に、`bypassPermissions` モード（確認を全部飛ばすモード）やシェルの許可ルールの下で、**確認なしに実行されていた**というものです（報告 anthropics/claude-code#96300）。

昨日は「同じコマンドに `~` やワイルドカードへの出力リダイレクトが混ざっていると保護が外れる」でした。今日は「`bash -c` の中に隠れていると外れる」です。**同じ保護を別の書き方ですり抜ける穴が、2日続けて見つかった**ということになります。

### 会話が長くなりすぎたときの扱いが改善されました

2つあります。

**1つめ**: auto モード（Claude がある程度自分で判断して進むモード）には、送られる内容を手元で点検する仕組み（クライアント側の安全性分類器）があります。会話が長くなってこの点検ができなくなると、これまでは **ツール呼び出しのたびに確認を求める、あるいは失敗する** 状態になっていました。今は **自動で要約圧縮される**ようになりました。

**2つめ**: 直前の返答がトークン使用量を「0」と報告した場合に、長い会話が自動圧縮されず **「Prompt is too long（プロンプトが長すぎます）」で失敗していた**のが直りました。

このセッションのように長く続く会話が、まさに当たっていた条件です。

### Ctrl+C で消した入力が、↑キーで戻ってくるようになりました

入力途中の文章を Ctrl+C で消してしまったとき、**空の入力欄で ↑ を押すと下書きが戻ってきます。** 貼り付けたテキストや画像も含めて戻ります。

### セッションの再開（`--resume`）まわりで5件の修正

長く続くセッションに直接関わる部分なので、まとめて説明します。

- **応答の途中で API がタイムアウトするとターンが失敗していた**のを修正。対話していないセッションとサブエージェントは、途中まで来た応答から続けるようになり、思考だけの応答は再試行されます
- `--resume` が、**圧縮が復元したばかりのファイルや文脈を落とす**ことがあったのを修正
- 再開したセッションが **ターンの最後の応答を保存しない**ことがあり、次の `--resume` で「質問に答えていない」状態に見えていたのを修正
- 再開中に同じセッションがファイルを書き換えると、**途中で切れた記録を読み込む**ことがあったのを修正
- **2.1.286 以前で始めた会話を再開すると、それ以前のモデルの思考が消えていた**のを修正

### MCP サーバーが OAuth の追加権限を求めたときに、再認証を促すようになりました

ツール呼び出しの最中に MCP サーバーが「もっと広い権限が必要」と言ってきた場合、**再認証を求めるプロンプトが出る**ようになりました。

あわせて、**「終わったかどうかをサーバー側が報告できない」場合の URL プロンプトは、利用者が「I'm done, continue（終わりました、続けて）」と言うまで待つ**ようになりました。ブラウザ側での作業を先に終わらせられる、という変更です。

### MCP のツール呼び出しが2回走る不具合（今日は別の原因）

リモートの MCP サーバーの応答が **16MB を超えた場合、または解析できなかった場合**に、ツール呼び出しが2回実行されることがありました。

昨日の「プロトコルのバージョンが変わったとき」とは別の原因です。**2日連続で、違う原因の「2回実行」が直っている**ことになります。

気になるなら聞けること: 「Routine が同じことを2回やってた形跡がないか、見ておいた方がいい?」

### フック（自動処理）が黙って飛ばされる不具合

`PreToolUse`（ツール実行前）と `PermissionRequest`（許可要求時）のフックが、**一致判定に失敗したり、ツールの入力を JSON に変換できなかった場合に、黙って飛ばされていました。** 今はその呼び出し自体が **ブロックされる**ようになりました。

「安全のために置いたフックが、気づかないうちに効いていなかった」という種類の不具合です。

### `.claude/rules` と入れ子の CLAUDE.md が、書き込み時に読まれていなかった

パスごとに適用される `.claude/rules` と、フォルダごとに置いた CLAUDE.md が、**Read（読み取り）のときだけ読み込まれ、Write や Edit でそのフォルダのファイルを作ったり変えたりしたときには読み込まれていませんでした。**

「このフォルダではこう書いて」というルールが、まさに書き込むときに効いていなかったことになります。

### 他のセッションにメッセージが届かなかったとき、嘘の「配達済み」が出なくなりました

Claude が別のセッションにメッセージを送り、**相手のセッションがそれを保留した場合に「配達済み」と報告していました。** 今は「届いていない」と、どのセッションかを名指しで伝えます。SDK セッションでは、ターンの途中でそれを知ることもできるようになりました。
