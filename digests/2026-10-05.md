## ③ 今日の変更（説明つき）

### 許可ルールをすり抜ける穴が、5件まとめて直りました

「このコマンドは拒否」「このコマンドは必ず確認」というルール（deny ルール / ask ルール）が、**書き方を変えると効かなくなる**という穴です。今日直った5件を並べます。

1. **`bash -c` のような複合コマンドの、入れ子になった部分**に対する拒否・確認ルールが、**管理されたマシンで、利用者が入れた Mod の承認に負けていた**
2. **`Read` の拒否ルールが、シンボリックリンク（別の場所を指す小さなファイル）経由で @ で言及・変更・IDE で選択したファイルに適用されていなかった**
3. Bash の拒否・確認ルールが、**環境変数を前置きした形で、その値が展開されるコマンド**を見落としていた（例: `TZ="$HOME" rm -rf build`）。サンドボックスがコマンドを自動許可している場合
4. 同様に、**コマンドの前に単独の変数代入が置かれている**と、サンドボックス自動許可の下で拒否・確認ルールが飛ばされていた
5. **利用者が入れたプラグインが、組織が管理している MCP サーバーのサインイン用ツールの説明文を書き換えられた**

**5つめは性質が違います。** 他の4つは「書き方を変えると判定をすり抜ける」ですが、これは「利用者のプラグインが、組織側が決めたものの表示内容を上書きできる」というものです。サインインを促す文面が書き換えられるということは、偽の案内を出せたということになります。

**この系統、今週の流れをまとめます。**

- 10/2: `rm` の確認が、出力リダイレクトと組み合わせると外れる
- 10/3: `rm` の確認が、`bash -c` の中に書くと外れる
- 10/5（今日）: 上記5件

「同じ保護を、別の書き方ですり抜ける穴」が **4日間で7件**見つかっています。原さん自身が何かする必要はありませんが、傾向としてお伝えしておきます。

気になるなら聞けること: 「自分の環境で、確認なしで動くようにしてるコマンドってある?」

### 短いコードブロックでターミナルやブラウザが固まる不具合

2か所で同じ原因の修正が出ています。

- **ターミナルが固まる**: 閉じられていない `<script>` タグが多数ある、または `${` の入れ子が非常に深い短いコードブロックで発生
- **公開されたアーティファクトのページが、読んだ人のブラウザのタブを固める・落とす**: 閉じられていない `<script>` タグが多数ある短いコードブロックで発生

後者は **原さんが作ったページを見た人の側で起きる**種類の不具合です。

### 入れたばかりの Mod が、1回目のセッションで読み込まれない

Claude Code を更新した直後の **最初のセッション**で、インストール済みの Mod が読み込まれていませんでした。Mods は10月1日に入った機能なので、入れてみて「動かない」と見えていた可能性のある不具合です。

### プラグインが原因でセッションが落ちる・終了する不具合が4件

- プラグインの画面処理が **非同期で例外を投げる**と、監視下のセッションとバックグラウンドのセッションが終了していた
- 高さの無いプラグイン領域が膨らみ続けると、インターフェースのエラーでセッションが終了していた
- プラグインが、**ターミナルが知らない枠線スタイル**で Box を描くと、起動時に固まる・強制終了していた
- Mod の `ui.render` が書いた値が原因で行の描画が例外を投げると、「unrecoverable interface error」でセッションが終了していた（今はエンジンが自前の行を描く）

### エージェント（作業係）まわりの機能追加

- `agent.spawn` が teammate（チームメイト）向けに追加されました
- プラグインのフックイベント全体で **1つのエージェントIDが使われる**ようになりました
- `$.agent.list()` が **idle（待機中）と waiting（待ち状態）** を返すようになりました

## ④ 一行で流すもの

Claude Code 2.1.289 の残りです。判断は原さんに委ねます。

**Mods（画面描画の不具合）**
- タブ・はぐれたエスケープ文字・C1制御文字を含むテキスト、またはタブと CRLF 改行を含む短いテキストが、下の行に重なって描かれていたのを修正
- Mod のパネルや帯の右寄せ表示が、閉じるマークや `[-]` の下に描かれていたのを修正（どちらもターミナルの端から1列内側を保つように）
- Mod の `Client`（通信部品）が描画中に失敗すると、その Mod が描いた周囲すべてを巻き込んで落としていたのを修正（単独で失敗し、`ui.fault` を上げる）
- ターミナルが描画中に例外を投げると、Mod の `Client` 領域がそのセッションの最後まで失敗したままになっていたのを修正
- Mod の帯が描画に失敗すると、下のカードに一瞬「どいて」と伝えていたのを修正
- 失敗したプラグイン部品が、エラーメッセージの無い失敗で理由を `Error` または空欄で表示していたのを修正
- Mod の帯やパネルが描画に失敗したときに作者が見る行を改善（Mod の名前を挙げ、何も描かれなかったと明示）
- プラグインの入力欄の上の行が、全画面でバックグラウンドタスクのダイアログが開いている間、古い内容を表示していたのを修正
- プラグインのパネルが、リンクに localhost のアドレス・パス中の `@`・大文字のホスト名・`file:` パスを使っていると何も描画しなかったのを修正
- プラグインのコードパネルで大きなファイルを開く速さを改善（強調表示の配置を最終幅で1回だけ行う）

**プラグインのコマンド**
- `plugin list` / `plugin eval` / `plugin update` が、ローカルフォルダのマーケットプレイスから入れたプラグインの古い内容を表示していたのと、シンボリックリンクされた `--plugin-dir` のホットリロード（再起動せずに読み直す仕組み）を修正
- `claude plugin validate` が、フォルダにマーケットプレイスのマニフェストも入っているとそのプラグインを飛ばしていたのを修正
- `claude plugin validate` が、Anthropic のマーケットプレイス自身のプラグインを不合格にし、`--json` で問題のない `plugin.json` を列挙していたのを修正

**VSCode 拡張（1件）** — PROFILE.md の取り決めにより省略しています。内容は 2.1.288 の `claude auth status` の変更の差し戻しです（サインアウトが頻発する原因になっていた可能性があるため）。

**ドキュメント**
- 日本語ドキュメントのページ数が **219 → 220** に増えました。どのページが増えたかは、目次の URL 一覧に差分が無いため **今日のソースからは特定できません**。
