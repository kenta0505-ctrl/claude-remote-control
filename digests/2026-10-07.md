## ② ⚠️ 今の使い方が変わるもの

価格の変更とモデルの廃止予告はありません。一方で、**挙動が変わるもの**が今日は多いので並べます。

### 1. Web検索の回数制限の数え方が変わりました

対話セッションの Web検索の予算が、**「200回使い切ったら終わり」から「1時間あたり100回のペースで回復していく」**方式に変わりました。

- 回復ペースは `CLAUDE_CODE_WEB_SEARCH_REFILLS_PER_HOUR` で変えられます。**0 にすると回復なし**になります。
- 長く続くセッション（この digest セッションのような）には有利な変更です。1日に何度も検索しても止まらなくなります。

### 2. Routine（定期実行）が、非公開アーティファクトを承認なしで作れるようになりました

スケジュール実行と「Run now」で動く Routine は、**原さんだけが見られる新しいアーティファクトを、承認を求めずに公開（作成）する**ようになりました。

- **コネクタや他のアクセスを要求するアーティファクトは、今も承認を求めます。**
- 「誰にも見えない自分専用のページ」だけが、無確認で作られるようになったということです。

### 3. 確認を求めるようになったコマンドが3種類

これまで無確認で動いていたものが、**確認を求めるようになりました**。

- **`pyright`**（Python の型チェックツール）— 読み取り専用コマンドの扱いをやめました
- **`ps` コマンドのより多くの書き方** — 無確認で動いていたものが確認を求めるようになりました
- **`rg` や `git grep` のような読み取り専用コマンドで、引数がワイルドカードとして展開される場合** — 自動承認をやめました

逆に、**確認が減った**ものもあります。厳格サンドボックスモードがユーザー設定・管理設定・`--settings` のいずれかで設定されている場合、`FOO=bar python3 app.py` のように環境変数を前置きしたインタープリタのコマンドが無確認で動くようになりました。

### 4. ローカル MCP サーバーの接続方式の既定が変わりました

ローカル（stdio）の MCP サーバーとの接続が、**プロトコルバージョン 2026-07-28 を既定で交渉する**ようになりました。Bedrock / Vertex / Foundry 経由も含め、すべての新規インストールが対象です。

**この更新後に繋がらなくなった MCP サーバーがある場合**、`MCP_PROTOCOL_NEGOTIATION=legacy` で以前のやり方に戻せます。

### 5. プロジェクトの設定ファイルから操作できなくなったものが2つ

リポジトリに置いた設定ファイル（`.claude/settings.json` など）で勝手に有効化されないよう、締められました。

- **Claude in Chrome** は、プロジェクトの設定ファイルから有効にできなくなりました。`--chrome`、`/chrome`、またはユーザー設定を使います。
- **`CLAUDE_CODE_DISABLE_ATTACHMENTS`** は、リポジトリの `.claude/settings.json` / `.claude/settings.local.json` から設定できなくなりました。シェル・ユーザー設定・管理設定からは今も設定できます。

### 6. その他の挙動変更

- **エージェント名は最大256文字**になりました。長い名前は拒否され、スキルやプラグインファイルの `name` が超えている場合は無視されます。
- **`claude plugin test`** が、テストが登録したフック内の `expect` の失敗や、エンジンが拒否したスタブ応答で、**黙って成功扱いにせず失敗する**ようになりました。
- **`/code-review` の medium（中）**が、専用の調整が入っていないモデル（Opus 5.5 と Sonnet 5.5 を含む）でも、整理（cleanup）と CLAUDE.md の作法に関する指摘を出すようになりました。
- **Claude apps gateway** の対応 PostgreSQL の下限が 14 から **11 に下がりました**（対応範囲が広がった方向です）。
- クラウドセッション内蔵の `gh api` が、`GH_HOST` や `GH_REPO` で github.com 以外のホストを指定すると**拒否する**ようになりました（`--hostname` か完全な URL を使う）。

（継続中のものを再掲します。**Claude Sonnet 4.5 が 2026年11月30日に API から停止**します。原さんの使用モデルは Claude Opus 5 なので直接の影響はありません。）

## ③ 今日の変更（説明つき）

### 「Security:」と明記された修正 — ネットワーク経路のファイル読み取りで確認が飛ばされていた

CHANGELOG で **`Security:` という接頭辞がついた項目**です。この digest を始めて以来、この書き方を見たのは初めてです。

内容: **PreToolUse フックの承認と auto モードが、ネットワーク経路（UNC パス）からのファイル読み取りで、許可プロンプトを飛ばしていた。**

UNC パスとは Windows で `\\サーバー名\共有名\...` と書く、ネットワーク上の共有フォルダを指す書き方です。手元のファイルを読むときは確認が出るのに、**ネットワーク越しのファイルは確認なしで読めていた**ということになります。

### 「読み込み中にリンクを差し替える」と、承認していないファイルが読める穴が3件

3件とも仕組みは同じです。**承認を取った直後、実際に読む前のわずかな隙に、そのパスが指す先（シンボリックリンク）を別のファイルに差し替えると、承認していないファイルの中身が返ってくる**というものです。

今日直った3件（いずれも macOS と Windows）

1. **画像の読み取り**（2.1.290）
2. **@ で言及したファイル**（2.1.290）— 読み取りブロックや `--restricted` の下でも、作業ディレクトリの外のファイルを読めていた
3. **ノートブックと PDF の読み取り**（2.1.292）

「確認を出してから実際に読むまでの間に対象が入れ替わる」という類の問題で、1つの手口が3つの入り口で順に塞がれた形です。

### 利用者のプラグインが、組織の仕組みを壊せる穴が4件

10月5日にも同系統が1件出ていましたが、今日は4件です。

1. **利用者が入れた Mod が、組織のプラグインを無効化させられた**（2.1.290）→ 今は Mod 側が無効化される
2. **利用者が入れた Mod が、組織のガード（守りの仕組み）に検査を飛ばさせられた**（2.1.290）→ そのような Mod は無効化される
3. **組織のプラグインが、自身の再読み込み時や他のプラグインがクラッシュした後に無効化されていた**（2.1.292）— 利用者が入れた Mod が追加した `$` の名前を、組織のプラグインが返した場合。今は Mod 側が無効化される
4. **改ざんされたディスク上の設定キャッシュが、設定の取得に失敗している間に、内蔵のポリシープラグインをオフにしたり差し替えたりできた**（2.1.292）

いずれも「組織が決めたルールを、利用者側の都合で無効化できてしまう」方向の穴でした。

### Routine（定期実行）に直接関わる修正が10件以上

原さんの環境に一番近い部分なので、まとめて並べます。**「予定したはずの処理が動かない／余分に動く」**という性質のものが揃っています。

**動かなくなるもの**

- `/resume`、`/branch`、`/clear` の後に作った予定タスクが **二度と発火しなかった**（2.1.292）
- 予定タスク（間隔つきの `/loop`、リマインダー）が、**会話が圧縮された後は再開時に戻ってこなかった**（2.1.290。この修正以降に行われた圧縮が対象）
- 前面で設定した予定タスクが、**← または `/background` で裏に回すと二度と発火しなかった**（2.1.290）
- バックグラウンドセッションの `/loop` が、**プロセスが再起動すると（クラッシュ後など）黙って止まっていた**（2.1.292）。待機中の起床予定が失われるため
- クラウドセッションが、**コンテナ再起動で `/loop` の起床予定や予定タスクを失ったまま眠り続けていた**（2.1.290）→ 今は Claude に知らされ、再設定できる
- クラウドセッションで、**Claude がそれらを読んでいる最中にメッセージが再試行・編集されると、予定タスクやキューの通知が失われていた**（2.1.292）
- 一回限りの `claude -p` 実行が、**設定した起床予定を落としていた**（2.1.292）
- 予定タスクのファイルへの書き込みが**ミリ秒差で2回続くと、その後の作成・削除が無視されていた**（2.1.292）

**余分に動くもの**

- 繰り返しの予定タスクが、**再開・再起動・フォークのたびに1回余分に走っていた**（2.1.290）
- `/loop` などセッション限定の繰り返しタスクが、**Linux のサンドボックス内 Bash コマンドの後、または `.claude/scheduled_tasks.json` を削除した後に、1回余分に走っていた**（2.1.290）

**その他**

- 予定タスクが無くなったバックグラウンドセッションが、**約20秒後に Completed に移り**、アイドル時に更新・停止できるようになりました（2.1.290）
- `/loop` の起床待ちのバックグラウンドセッションは、**更新時やメモリ不足時にも動かしたまま維持される**ようになりました（2.1.290）。再起動や停止で起床予定を黙って失う恐れがあったため

### 2.1.291 は、直前のリリースの不具合を直すだけの緊急リリース

2項目しかありません。どちらも「リグレッション」（それまで動いていたものが壊れた、という意味）の修正です。

- **2.1.290 で入った不具合**: クラウドセッションが **許可プロンプトへの回答を落とす**ことがあった
- **2.1.288 で入った不具合**: 終了するときに **セッションの最後のメッセージが失われる**ことがあった

2.1.290 が190項目の大きなリリースで、その直後に修正版が出た、という流れです。

### サブエージェントを effort（念入りさ）指定で動かせるようになりました

Agent ツールに **`effort` パラメータ**が追加されました。サブエージェント（本体とは別に動く作業係）を、指定した effort レベル（モデルがどれだけ念入りに考えるかの設定）で動かせます。

あわせて、**`permissionMode: auto` を指定したサブエージェントが、auto モードが使えない状況（設定で無効、サーキットブレーカー作動中、対応していないモデル）でも auto モードに入っていた**のが直りました。

### Windows の `rm -rf` で、ホームフォルダの別表記が見逃されていた

ホームフォルダやドライブを **8.3形式の短い名前**（`PROGRA~1` のような昔からの短縮表記）や、Windows の別の綴り方で指した `rm -rf` が、**「それを削除する操作」として扱われていなかった**のが直りました。

`rm` 系の保護の穴は 10/2・10/3・10/5 にも出ていて、今日も続いています。
