## ② ⚠️ 今の使い方が変わるもの

### 1. Managed Agents の `web_fetch` が、取得できる URL を会話の中に出たものに限定

Claude Managed Agents（Anthropic 側で動かすエージェント）の `web_fetch` ツールが、**その会話に既に出てきた URL しか取得しない**ようになりました。リリースノートに「**情報の持ち出し（data exfiltration）のリスクを減らす**ため」と明記されています。

**「出てきた」として数えられるもの**

- 利用者のメッセージの本文に書かれた URL
- `web_search` の結果に出てきた URL
- `web_fetch` が前に取得したページの中にあった URL

**数えられないもの**（取得しようとすると `url_not_in_prior_context` エラーが返る）

- **Claude 自身の出力にだけ出てきた URL**
- エージェントのシステムプロンプトに書かれた URL
- 添付した文書の中の URL
- **`bash`・`read`・MCP ツールなど、ツールの出力に出てきた URL**

取得させたい URL は、`user.message` イベントの本文に送る、という形になります。

この変更の意味を一言で言うと、「**Claude が自分で組み立てた URL や、読み込んだファイルの中にあった URL には、勝手にアクセスしに行かない**」です。ファイルの中身を URL に埋め込んで外部に送る、という手口を塞ぐものです。

### 2. claude.ai のコネクタも、MCP プロトコルの既定が 2026-07-28 に

昨日「ローカル（stdio）の MCP サーバー」について同じ変更をお伝えしましたが、今日は **claude.ai のコネクタ**（Square / Gmail / Google Drive / Google Calendar のような接続）が対象です。

- フラグを取得しないインストールで、**プロトコルバージョン 2026-07-28 を既定で交渉する**ようになりました
- **繋がらなくなった場合は `MCP_PROTOCOL_NEGOTIATION=legacy`** で以前のやり方に戻せます（昨日と同じ環境変数です）

原さんは Square / Gmail / Google Drive / Google Calendar のコネクタを使っているので、**こちらは原さんの環境に関係する変更です。** ただし「繋がらなくなる」と決まった話ではなく、「繋がらなくなった場合の戻し方が用意されている」という段階です。

気になるなら聞けること: 「コネクタがちゃんと動いてるか、今のうちに確認しておいた方がいい?」

### 3. Claude Haiku 3.5 が、Bedrock でも停止済みになりました

価格表の表記が変わりました。

- 旧: 「**retired, except on Bedrock and Google Cloud**（Bedrock と Google Cloud を除いて停止済み）」

つまり **Amazon Bedrock 上でも使えなくなりました**。残っているのは Google Cloud だけです。

### 4. Routine の実行が、テレメトリをオフにした環境でも承認なしで非公開アーティファクトを作るようになりました

10月7日に「スケジュール実行と Run now の Routine は、非公開アーティファクトを承認なしで作る」とお伝えしました。今日はその **テレメトリ（利用状況の送信）をオフにしている環境**でも同じ動作になった、という変更です。

あわせて、**テレメトリをオフにしている環境の Artifact ツールの許可プロンプトが、他の環境と同じ5つの質問に統一**されました。これまでは「他人のアーティファクトを読むたび」「データを編集するたび」に確認していたのが、そうでなくなります。

### 5. その他の挙動変更

- **MCP ツールの説明文の切り詰め位置が、2,048文字 → 16,384文字に拡大**（ツール検索を通してモデルが読み込む場合）

- **タブ位置の数え方が変わりました**: 画面の左端からではなく、**テキストが始まる位置から**数えます。2文字インデントされた回答の最初のタブ位置は、6セルではなく8セル目になります
- **背景色を自分で持たないアーティファクトのページが、オフホワイトではなく白で表示**されるようになりました

- **`claude agents` をバックグラウンドサービスごと止めた場合**（macOS、またはサービス未導入の Linux）: **動いているセッションは約1分で停止**します（その間に再実行しなければ）。そう伝える通知が出ます
- **アタッチ中のバックグラウンドセッションで、入力待ちの状態で Ctrl+C** を押しても、待機中の `/loop` の起床予定はそのままになりました。2回押すと切り離され、ループは動き続けます。**止めたい場合は Esc** です
- 組織の Mod が出すトースト（短い通知）が、他の Mod のトーストの後ろで待たず、**先に表示される**ようになりました
- 自己ホストランナー: `CCR_AUTO_MODE_ALLOW` / `CCR_AUTO_MODE_ENVIRONMENT` / `CCR_AUTO_MODE_SOFT_DENY` を、セッションの環境に渡すのをやめました

## ③ 今日の変更（説明つき）

### 「指示文として書いたフック」が、止めるべきものを通していた

**2.1.294 は、この系統の2項目だけの緊急リリース**です。

フック（自動処理）は、シェルコマンドや HTTP リクエストのほかに、**日本語や英語の指示文としても書けます**。「〜するコマンドをブロックして」のように書くと、Claude がその指示に従って判定します。

今日直ったのは、その **指示文として書いた `prompt` フックと `agent` フックが、ブロックすべきものを通してしまっていた**というものです。原文は以下です。

> Fixed `prompt` and `agent` hooks written as instructions (such as "Block commands that...") allowing what they should block

**「Block commands that...（〜するコマンドをブロックして）」という書き方をしていたフックが、効いていなかった**ということになります。安全のために置いたフックが、気づかないうちに素通りさせていた類の不具合です。

もう1件は改善です。

> Improved how `prompt` hooks on Stop and SubagentStop written as instructions (such as "Carry on if the build is broken") are judged, so Claude is less likely to stop early

Stop と SubagentStop に指示文で書いたフック（「ビルドが壊れていたら続けて」のような）の判定が改善され、**Claude が早めに止まってしまうことが減った**、という内容です。

### フックが起動できない・タイムアウトした場合に「通す」のをやめられるようになりました

**`onFailure: "block"`** が、コマンド型と HTTP 型のフックに追加されました。

これまでは、フックが **起動できない・タイムアウトする・予期しない終了コードで終わる**と、その処理は**そのまま通されていました**。`onFailure: "block"` を設定すると、そうした場合に**処理をブロックする**ようになります。

「安全のために置いたフックが動かなかったとき、通すか止めるか」を選べるようになった、ということです。前項の 2.1.294 の不具合と合わせて読むと、今週はフックの信頼性が焦点になっていることが分かります。

### 予定タスク・Routine 関連の修正が、今日もまた5件

今週ずっと続いている系統です。原さんの環境に一番近い部分なので、今日の分を並べます。

1. **一部の古い Routine が、保存されたプロンプトを Claude に一度も渡さずに実行を始めていた**（クラウドセッション）。該当する Routine は、今はプロンプトを渡して再実行されます
2. **停止した予定タスクが、巻き戻し（rewind）の後の再開で復活していた**。また、**圧縮の後に Esc や巻き戻しをしてから再開すると、予定タスクが失われていた**
3. **バックグラウンドセッションの `/loop` が、次の起床予定の時刻にそのセッションのプロセスが落ちていると、通知もなく止まっていた**。今はセッションがそう伝え、Claude にも知らされます
4. **`←` でバックグラウンドに移した自分でペースを決める `/loop` を、Esc で止められなかった**。待機中の起床予定を取り消すと通知が出るようになりました
5. **`/rewind` の後に送ったプロンプトが失われ、消したターンが戻ってきていた**（セッションをバックグラウンドに移した場合、または強制終了後に再開した場合）

1番目は「Routine が設定した内容と違うことをしていた」という、かなり重い種類の不具合です。

気になるなら聞けること: 「自分の Routine で、意図と違う動きをしてた日がないか確認できる?」

### リモート MCP サーバーの接続が、切れたまま戻らない／ループする不具合

ヘッドレス（画面なし）と SDK のセッションで、2つの問題が直りました。

- **15秒を超える障害の後、リモート MCP サーバーが接続されないままになっていた**
- **接続した直後に毎回切ってくるサーバーに、休みなく再接続を試み続けていた**。今は繰り返しの切断で待ち時間が延び、**最大30秒**になります

あわせて、**サーバーのエラー応答に、たまたまネットワークエラーの名前が含まれていると、リモート MCP の接続が切られていた**のも直りました。

さらに、**ページ送りのカーソルを繰り返す MCP サーバーに、接続ごとに同じページを最大20回要求していた**のも修正されています。

### ターミナルが固まる不具合が4件

今日は特に多いので、まとめます。

- **応答が数万行に達すると、ターミナルが固まり ctrl+c も効かなくなっていた**
- **数行ごとに引用が深くなっていく返答で、ターミナルが数秒固まり、メモリをギガバイト単位で使っていた**
- **非常に長い行・空行の長い連続・閉じていない文字列やヒアドキュメントを含むコードの構文強調で、数秒から数分固まっていた**
- **フックモジュールが数千段の入れ子になっているプラグイン**が、スタックオーバーフローの素っ気ないメッセージだけで読み込み・検証に失敗していた

### ファイルを読んでいないのに「読んだ」扱いになる不具合が2件

Claude がファイルを編集する前には、そのファイルを読む必要があります。その「読んだかどうか」の判定が2か所で誤っていました。

- **`cat` のような Bash コマンドが、中身を表示せずに終わった後**、そのファイルが「もう読んだ」扱いになっていた
- **ファイルの中身が変わったのに、更新時刻が進んでいなかった場合**、Edit がそのファイルを「完全に読んだ」扱いにしていた

どちらも「古い内容を元に編集してしまう」ことにつながる種類の不具合です。

### Haiku 4.5 の移行ガイドのページが無くなりました

Platform ドキュメントの URL 一覧から、**`models/haiku-4-5/migration-guide` が削除**されました。代わりに Haiku 5.5 のページ群が追加されています。

- 追加: `models/haiku-5-5/overview`、`models/haiku-5-5/migration-guide`、`models/haiku-5-5/whats-new-haiku-5-5`
- 追加: `build-with-claude/prompt-engineering/prompting-claude-haiku-5-5`
- 追加: `release-notes/system-prompts/claude-haiku-5-5`
- **削除: `models/haiku-4-5/migration-guide`**

昨日お伝えした「Haiku 4.5 がモデル比較表から外れた」と合わせると、**Haiku 4.5 の資料が段階的に片付けられている**ように見えます。ただし廃止予告はまだ出ていません。

### ターミナルが Claude Code の状態を表示できるようになりました

**Program Status Protocol（OSC 7501）** に対応しました。この規格を実装しているターミナルは、**Claude Code が「作業中」「こちらの入力待ち」「完了」のどれなのかを表示**できます。

## ④ 一行で流すもの

Claude Code 2.1.294 / 2.1.295 の残りです。判断は原さんに委ねます。

### 権限・セキュリティ

- 改ざんされた、サーバー管理の設定のキャッシュが、管理設定でプラグインを列挙・有効化しているマシンで、**本人のプラグインを「組織が管理しているもの」として数えさせられた**のを修正
- `--tools` と `--restricted` が、起動後に登録される内蔵ツールに適用されず、非推奨のツール名が呼び出し側のツール集合の外のツールに届いていたのを修正
- Mod のフックに、深く入れ子になったツール入力が**エラーも出さず途中で切られて渡されていた**のを修正。ガード（守りの仕組み）が、見ていない内容を通しうる状態でした
- Mod が、プラグインのフックワーカーの再起動中に再読み込みされる間に行った呼び出しが、別の Mod の `.catch` 付きガードフックをすり抜けていたのを修正（今は拒否される）
- Claude in Chrome が、ポート80 を明記したサイト拒否ルール（`host:80`）を、そのホストの平文 `http://` ページに適用していなかったのを修正
- Bash の許可チェックを、glob パターンに対する for ループについて修正（許可判定の精度が改善）
- `/ultrareview` のアップロードが中断されて `~/.claude/seed-admin` 以下に残った一時ファイルが、保持期間の整理で削除されなかったのを修正
- macOS: セッション開始時のファイル数の数え上げが、ホームフォルダまたはその上で始めると他のアプリのデータに届き、「他のアプリのデータへのアクセス」の確認が出ることがあったのを修正

### MCP

- MCP ツールが返す CSS・JavaScript・XML のファイルが `.bin` として保存され、Read ツールが拒否していたのを修正。フォントとアイコンのファイルも固有の拡張子が付くように
- MCP サーバーのリソース一覧を Claude が待っている間、中断してもタイムアウトまでターンが終わらなかったのを修正
- 長時間かかる MCP ツールの呼び出しを、タスクパネルや接続中のクライアントから止めたとき、Claude に伝えられていなかったのを修正
- バックグラウンドに移った MCP ツール呼び出しの通知が、短縮されたタスクIDを表示していたのを修正
- 対話していないセッションが、リクエストで使わない MCP サーバーについて「認証が必要」と伝えていたのを修正
- ヘッドレスと SDK のセッションで、MCP のサインインや再接続が遅れて完了すると、`setMcpServers()` で設定したサーバーを利用者自身のものとして再掲していたのを修正

### モデル・リクエスト

- `[1m]` のモデルで、ゲートウェイ・Bedrock・Vertex・Foundry が context-1m ベータを拒否すると全リクエストが失敗していたのを修正（今はそれを外して再送する）
- `CLAUDE_CODE_RETRY_WATCHDOG_MAX_WAIT_MS` を追加。無人の再試行モード（`CLAUDE_CODE_RETRY_WATCHDOG`）が 429 と 529 のエラーを待つ時間に上限を設けられる
- Claude 3 Opus と Claude 3.x Sonnet のセッションに、それらのモデルが拒否するツール検索が提示されていたのを修正（機能フラグが使えない環境で）
- `/model` が、Max の effort を選んだとき「新しいセッションの既定として保存しました」と言っていたのを修正（**Max は現在のセッションにだけ適用されます**）
- `/advisor` のダイアログが、もう使えない保存済みのアドバイザーモデルにチェックマークを表示していたのを修正（今は「No advisor」で開く）
- `availableModels` に列挙された Fable のモデルが、Claude apps gateway にサインインしたセッションの `/model` 選択画面に出なかったのを修正
- `xhigh` と `max` の effort で、Web検索と `agent` フックの評価がずっと時間がかかっていたのを修正

### Claude apps gateway（8件）

- `timeouts.upstream_ttfb_ms` に対応（Bedrock・Vertex・Foundry などのクラウド上流で、ストリームが開始するまでの時間を制限。超えるとフェイルオーバーするか 502 になる）
- 各上流に任意の `models` 一覧を追加（列挙されたモデルだけがそこに送られる。フェイルオーバー時も同様。項目内の `*` 1つはワイルドカード）
- `inference` 監査イベントに `upstream_request_id` を追加（Bedrock・Anthropic API などの上流のリクエストID。サポート問い合わせ用）
- 成功した推論の応答に `request-id` ヘッダを追加（Claude Code のテレメトリの `request_id` がゲートウェイの監査ログと一致するように）
- 管理画面の支出表示が、開発者のセッションがグループを持たなくなった後も、古いグループとグループ上限を表示していたのを修正
- `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` が、`/usage` とステータスラインのゲートウェイの支出上限を隠していたのを修正。支出上限の要求は、そのセッションがサインインしているゲートウェイに送られます
- PostgreSQL のデータベースが読み取り専用の間、**30秒ごとに警告を記録**するよう改善（何が失敗し、どう回復するかを明記）
- Bedrock 上でのトークン数の数え方を改善（`/context` と大きなファイルの読み取りが使う）。**1トークンのモデル呼び出しではなく AWS の CountTokens API から取得**するようになりました。使うには `bedrock:CountTokens` の権限が必要です
- `models:` に列挙されていないモデルを、AWS の米国地域外の Bedrock リージョンで扱う方法を改善（AWS は常に拒否していた。今は自分のリージョンで試し、拒否されたら追加すべきモデル名を示す）
- `desktop` ポリシーで、同梱の Claude Desktop スキーマが知らないキーが設定されていても、警告を出して起動・提供するよう変更（新しい Desktop の設定のためにゲートウェイを更新しなくてよくなる）
- `forceLoginMethod: "gateway"` と `forceLoginGatewayUrl` を、管理設定が無いマシンの**自分のユーザー設定でも使える**ように（`/login` がそのゲートウェイで開く）
- `claude_code.auth` の OpenTelemetry のログインイベントが、ゲートウェイへのサインインで出ていなかったのを修正

### プラグイン・Mods（機能追加）

- `$.ui.notify` を追加。Mod が、利用者自身の通知設定を通してネイティブ通知を出せる（どのチャンネルから出たかも示す）
