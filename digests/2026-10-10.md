## ② ⚠️ 今の使い方が変わるもの

### 1. Claude 4.7 以降のモデルは、同じ文章で約30%多いトークンになります

価格表の「トークンとは何か」の説明文が書き換わり、重要な情報が追加されました。原文の要点です。

- 旧: 「1トークンは英語で概ね4文字、または0.75語。正確な数は言語と内容で変わる」
- 新: 「同じ文章が何トークンになるかは、**モデルのトークナイザー（文章をトークンに切り分ける仕組み）**、言語、内容の種類によって決まる。**Claude 4.7 以降のモデルと Claude Mythos Preview は、同じ文章で以前のモデルより約30%多いトークンを生成する、新しいトークナイザーを使う**」

特定のモデルで何トークンになるかは、そのモデルのIDを指定して token counting（トークン数え上げ）で確認するよう案内されています。

**これが意味すること**: モデルを 4.6 以前から 4.7 以降に変えると、**文章量が同じでもトークン数が約1.3倍になります**。入力・出力の単価が同じでも、請求額は増える方向です。これは今日新しく起きた変更ではなく、**これまで明記されていなかった事実が明記された**という性質のものです。

原さんの使用モデルは Claude Opus 5 で、これは 4.7 以降の世代にあたります。**既に新しいトークナイザー側です。**

### 2. Claude Haiku 5.5 で壊れるコードの一覧が、3点から9点に増えました

昨日お伝えした「Haiku 4.5 向けに書いたコードは Haiku 5.5 で壊れうる」の説明が、大幅に詳しくなりました。**400エラーを返すもの**は以下です。

1. 手動の拡張思考（`budget_tokens`）
2. **サンプリングのパラメータ `temperature`・`top_p`・`top_k`**（新規）
3. **アシスタントメッセージの prefill**（返答の先頭を指定しておく手法）（新規）
4. **`computer_20250124`**（新規）。代わりに Claude API と Google Cloud では `computer_toolset_20260801`、Amazon Bedrock では `computer_20251124` を使う
5. **`system`・`tools`・それ以前のターンを変更した後に thinking ブロックを送り返すリクエスト**（新規）

**400エラー以外**の注意点

6. **Amazon Bedrock では、Haiku 5.5 で構造化出力（structured outputs）が使えません**（新規）
7. 適応思考が既定でオンなので、応答が `thinking` ブロックから始まることがある
8. **その thinking ブロックの本文は、`thinking.display` を `"summarized"` にしない限り省かれます**（新規）
9. 同じ文章がより多くのトークンとして数えられる

### 3. Haiku 5.5 の「長さで2段階」の価格の数え方が明確になりました

昨日は「プロンプトが10万トークンを超えると高い価格」とだけ書かれていましたが、今日は数え方が明記されました。

- **リクエストのプロンプトの長さは、入力トークンのすべてを数えます。キャッシュの読み取りと書き込みも含みます。**
- **各リクエストは個別に価格が決まります。** プロンプトの一部がキャッシュヒットだったとしても、しきい値を超えていれば高い価格になります。
- **以前のリクエストは、請求されたときの価格のまま**です（後から変わりません）。

つまり「キャッシュに乗っているから短い扱いになる」ということはありません。

あわせて、**US限定推論（`inference_geo` パラメータ）の1.1倍の係数が、Haiku 5.5 では10万トークン超の高い価格にも適用される**ことが明記されました。

### 4. Google Cloud の regional endpoint の対象が狭まりました

価格表の記述が変わりました。

- 旧: 「Google Cloud は3種類のエンドポイントを提供: グローバル、マルチリージョン（地理的範囲内での動的ルーティング）、リージョナル」
- 新: 「Google Cloud は**これらのモデルにはグローバルとマルチリージョンを提供し、リージョナルは Claude Sonnet 4.6 以前のモデルに提供する**」

つまり **新しいモデルでは regional endpoint（特定のリージョンに固定する接続）が使えません。**

### 5. MCP ツールの説明文の上限が 2,048 → 4,096 文字に

最初から送られる MCP ツールの説明文と、MCP サーバーの指示文の既定の上限が、**2,048文字から4,096文字**になりました。

（昨日お伝えした「ツール検索を通して読み込む場合は 16,384文字」とは別の、こちらは「最初から送る分」の上限です。）

### 6. `←` の挙動が変わりました

**セッションをバックグラウンドに移している最中に始まったターンや `!` コマンドは、見えないところで完走せず、停止される**ようになりました。

（継続中のものを再掲します。**Claude Sonnet 4.5 が 2026年11月30日に API から停止**します。原さんの使用モデルは Claude Opus 5 なので直接の影響はありません。）

## ③ 今日の変更（説明つき）

### Shift-JIS などのファイルを編集すると、日本語がすべて壊れる不具合

**今日のいちばん原さんに近い項目です。**

`Edit` と `NotebookEdit` が、**UTF-8 として正しくないファイル**（Windows-1252、**Shift-JIS**、GBK など）を編集するとき、**非ASCII文字をすべて置き換えてしまっていました**。

Shift-JIS は日本語のファイルで広く使われている文字コードです。つまり **Shift-JIS で保存された日本語のファイルを Claude に編集させると、日本語の部分が全部壊れていた**ということになります。

**今は、そうした編集は拒否されます。** 直したわけではなく、「壊すくらいなら触らない」という形の修正です。

気になるなら聞けること: 「自分が Claude に触らせてるファイルが UTF-8 かどうか、確認できる?」

### 危険な `rm -rf` の確認漏れが、今日も1件

今週ずっと続いている系統です。今日の分は Windows です。

**Git Bash で `rm -rf /c/Users/<ユーザー名>`（ホームフォルダ）を実行したとき、bypass permissions モード（確認を全部飛ばすモード）で確認が出ていなかった**のが直りました。

この系統の今週の記録です。

- 10/2: 出力リダイレクトと組み合わせると保護が外れる
- 10/3: `bash -c` の中に書くと外れる
- 10/5: 環境変数の前置きなど5件
- 10/7: Windows の 8.3形式の短い名前で指すと外れる
- **10/10（今日）: Git Bash での `/c/Users/<名前>` 表記で外れる**

### 管理設定のフックが、拒否してもターンが終わらなかった

組織が管理設定で置いたフックの不具合が2件です。

- **`"continue": false` でツール呼び出しを拒否する管理設定の `PreToolUse` フック**と、**ツール呼び出しをブロックする管理設定の `prompt` フック**が、**その呼び出しは拒否するもののターンを終わらせていなかった**
- 管理設定の `PostToolUse` フックが、一部のセッションで `updatedMCPToolOutput` を適用していなかった

あわせて、**`UserPromptSubmit` フックや Mod の `prompt.submit` フックの実行中に Esc を押す・中断すると**、ヘッドレスのセッションが終了する・打ったプロンプトが消える・**検査を通っていないプロンプトがそのまま通る**という不具合も直りました。

「安全のために置いたフックが、気づかないうちに素通りさせていた」という系統が、昨日に続いて今日も出ています。

### 秘密情報のマスク漏れが、また1件

共有される記録とデバッグログの秘密情報のマスク処理が、**値のないキーの後に続く値を一部取りこぼしていた**のが直りました。**シェルの文字列の中に書かれた JSON** も対象です。

この系統は8月末からほぼ毎日続いています。

### Read ツールが、大きなテキストファイルを1回で読めるようになりました

`allow_large` オプションが追加されました。**Claude がファイル全体を必要としていて、コンテキスト（一度に扱える文章量）に余裕がある場合**に、通常のサイズ上限を超えてテキストファイルを1回の呼び出しで読めます。

### サブエージェントが、本体より早く自動圧縮できるようになりました

サブエージェント（本体とは別に動く作業係）の設定と `--agents` の定義に **`autoCompactWindow`** が追加されました。本体の会話の設定より**早いタイミングで自動圧縮**（会話を要約して縮める処理）を始められます。

あわせて **`CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL`** が追加され、**ワークフローのエージェントだけを1つのモデルで動かし、他のサブエージェントは自分のモデルを保つ**ことができるようになりました。

### Managed Agents に動的ワークフロー（beta）が入りました

Claude Managed Agents（Anthropic 側で動かすエージェント）で、**エージェント自身がワークフローを書ける**ようになりました。`managed-agents-2026-04-01` のベータヘッダが必要です。

- 想定される用途として「**数百件の文書をレビューするような、部品が多い作業**」が挙げられています
- **ワークフローとは「多数のエージェントを段階（フェーズ）に分けて実行し、その結果をまとめるプログラム」**です
- サーバーが**バックグラウンドで「ワークフロー実行（workflow run）」として動かします**
- 有効化は、エージェントの `multiagent` 欄を `{"type": "multiagent_20261001", "workflows": {"type": "enabled"}}` に設定
- エージェントに「いつ実行を始めるか」を**システムプロンプトで伝える**
- 各実行は、セッションのイベントストリームの **`workflow_run.*` イベント**で追えます

ドキュメントに `managed-agents/workflow-runs` と `managed-agents/session-threads` の2ページが新設されています。

### Claude Code のドキュメントの目次が大きく再編されました

**ページの追加も削除もありません**（URL の一覧に差分がゼロでした）。変わったのは**目次の構造**です。

- 新しく「**Overview**」という最上位の区分ができ、その下に Getting started / Core concepts / Use Claude Code / Platforms and integrations が入りました
- 「Use Claude Code」の下に **Agents and parallel work / MCP / Skills / Artifacts / Automation / Guides / Troubleshooting** という小区分ができました
- プラグイン関連が **Plugins / Use plugins / Create plugins / Mods / Run a marketplace / Manage plugins for your organization / Troubleshooting / Reference** に整理されました
- 管理者向けが **Setup and access / Deployment / Gateways / Usage and costs / Security and data / Adoption** に整理されました
- 設定関連が **Settings / Permissions and sandboxing / Environments / Model and responses / Interface / Reference / Glossary** に整理されました
- Agent SDK も **Build agents / Core concepts / Input and output / Extend with tools / Customize behavior / Control and observability / Deployment / SDK references** に整理されました

区分の見出しページが主要なページを改めて列挙する形になったため、同じページが目次に2回出てくる箇所があります。**情報が増えたわけではなく、並べ替えです。**

### Windows の PowerShell の許可判定が、1KB から 32KB まで効くようになりました

**約1KB を超える PowerShell のコマンドが、常に許可を求めていた**のが直りました。**許可ルールと「読み取り専用かどうか」の判定が、32KB まで適用される**ようになりました。

あわせて、**終了時に stdio の MCP サーバーが強制終了されていた**のも直りました。今は先に標準入力を閉じ、**300ミリ秒後もまだ動いていればプロセスツリーを終了**します。
