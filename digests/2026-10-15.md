## ② ⚠️ 今の使い方が変わるもの

価格の変更とモデルの廃止予告はありません。一方で、**設定が効かなくなりうる変更**が今日は複数あります。

### 1. MCP の許可ルールが、名前の一部一致で効かなくなりました

**既存の設定が効かなくなる可能性のある変更です。**

- 旧: `mcp__a` という許可ルールが、**`a__b` や `a_` という名前のサーバーにも効いていました**
- 新: **その名前のサーバーだけに効きます。** サーバー名に `__`（アンダースコア2つ）が含まれる場合は、**`mcp__<正規化後の名前全体>__*`** と書く必要があります

同じ変更が、エージェントの `tools:` の一覧にも入りました。**名指しした MCP サーバーのツールだけを取る**ようになり、名前に `__` を含むサーバーは `mcp__<名前全体>__*` と書きます。

あわせて、**サーバーの正規化後の名前に `__` が含まれると、`mcp__<サーバー名>` の拒否ルールと確認ルールが効いていなかった**のも直りました。つまり「許可が広く効きすぎていた」側と「拒否が効いていなかった」側が、両方とも締められた形です。

気になるなら聞けること: 「自分の設定に MCP の許可ルールを書いてないか、確認してもらえる?」

### 2. クラウドセッションと Remote Control のコネクタも、MCP プロトコルの既定が 2026-07-28 に

10月8日に「ローカル MCP」、10月9日に「claude.ai のコネクタ」とお伝えした変更の続きです。今日は **クラウドセッションと Remote Control のコネクタ**が対象になりました。

- フラグを取得しないインストールで、**プロトコルバージョン 2026-07-28 を既定で交渉**します
- **繋がらなくなった場合は `MCP_PROTOCOL_NEGOTIATION=legacy`** で戻せます

**原さんの Routine はクラウドセッションで動くので、こちらは原さんの環境に関係する変更です。** Square / Gmail / Google Drive / Google Calendar の各コネクタが対象になります。

気になるなら聞けること: 「コネクタが今も全部つながってるか、見ておいた方がいい?」

### 3. アイドル圧縮が追加されました（既定でオン）

**20万トークンを超えた会話を約54分放置すると、1時間のプロンプトキャッシュが切れる前に自動で圧縮**されます。目的は「次のメッセージを送ったときに全部を再処理しないようにする」ことです。

- 20万トークンという下限は **`CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS`** で変えられます
- **オフにするには `settings.json` に `"idleCompaction": false`**
- どちらも **v2.1.290 以降**が必要です

この digest セッションのように「長く、1日1回だけ動く」会話は、まさにこの条件に当たります。

### 4. `UserPromptSubmit` フックの実行タイミングが変わりました

**`UserPromptSubmit` フックが、スキルやカスタムスラッシュコマンドが展開される前に走る**ようになりました。

つまり、**プロンプトをブロックするフックが、そのスキルやコマンドに埋め込まれたシェルコマンドも止める**ようになります。これまでは展開後だったため、埋め込みのシェルコマンドは止められていませんでした。

あわせて、**スキル自身の frontmatter に書いた `UserPromptSubmit` フックは、そのスキルを呼び出したプロンプトの「次の」プロンプトから走る**ようになりました。

### 5. フックが答えられないときは「通さない」に変わりました

**フックがブロックできる操作は、そのフックに操作内容を渡せない場合、または答えを受け取れない場合、通さずに拒否される**ようになりました。既に実行されてしまったツールについては、**その結果を Claude に渡さない**という扱いになります。

あわせて、**`PreToolUse` と `PermissionRequest` フックが返す `updatedInput` が、Claude 自身の入力と同じように検証される**ようになりました。知らないキーは落とされ、ツールが拒否する入力はその呼び出しを拒否します。

### 6. 終了時の挙動とフラグの変更

- **終了時に、停止を求めてから1.5秒後もまだ動いているバックグラウンドコマンドは強制終了**されます（全画面モードでは以前は動いたまま残ることがありました）
- **`claude remote-control` から `--sandbox` と `--no-sandbox` が削除**されました。効果がなかったフラグです。**今は渡すとエラーで終了します。** サンドボックス化は設定の `sandbox.enabled` で行います
- **再開コマンドの表示が、セッション名ではなくセッションIDを使う**ようになりました。理由が明記されています: 「**その行を貼り付けたときに、セッション名に含まれるものが実行されないようにするため**」

### 7. その他の挙動変更

- **大きなリクエストが、テレメトリをオフにしていても gzip 圧縮される**ようになりました。`CLAUDE_CODE_GZIP_REQUEST_BODIES=0` でオフにできます
- **ローカルのセッション記録に、各 API リクエストのシステムプロンプト・ツール・パラメータも記録される**ようになりました。目的は「共有を選んだ記録でリクエストを正確に再現できるようにする」こと。**共有するときは、これまでより多くの情報が含まれる**ことになります
- **WebFetch のページ読み取りが、Web検索と同じやり方で effort を決める**ようになりました（呼び出し元のモデルでは呼び出し元のレベル、そうでなければ設定が小さいモデルに与えるレベル）
- **Anthropic 純正の MCP サーバー（`api.anthropic.com`）のツール説明文とサーバー指示文が、4,096文字で切られず全文届く**ようになりました
- **claude.ai のコネクタプロキシと Anthropic ホストの MCP サーバーへのリクエストが、HTTP リダイレクトを追わなくなりました**（コネクタ自身のサーバーによるリダイレクトは対象外）。クラウドと自己ホストランナーのセッションの MCP プロキシからのリダイレクトも同様です
- **スキルとコマンドの読み込み**: ファイル名やフォルダ名に **見えない文字・文字方向を変える文字・空白に見える文字・`<`・`>`** が含まれるものは、改名するまで提示されなくなりました。`name:` にそうした文字が含まれる場合は無視されます
- **プラグインのフックとワークフローのスクリプト**が返す値の入れ子の上限が **28,000段** になりました（ワークフローのスクリプトは以前 100,000段でした）。超えると上限を明示したエラーになります
- **サイバーセキュリティの注意書きが、Cyber Verification Program への申請を求めなくなりました**
- `/ultrareview` のアップロード失敗時のエラーが、**`git add .` を提案しなくなりました**。理由は「`.env` のような追跡外のファイルをステージ・コミットしてしまう恐れがあるため」です
- **`/sandbox` のモード選択の表記が「Sandbox BashTool」から「Sandbox commands」に**変更
- Cowork のクラウドセッションで、**`PermissionRequest` フックがシェルコマンドとサブエージェントを承認できなくなりました**（それらのプロンプトは待機、または拒否されます）。また、フックの許可に含まれる `setMode` の更新は無視されます

## ③ 今日の変更（説明つき）

### Shift-JIS のファイル保護が、Write にも広がりました

**10月10日に Edit と NotebookEdit について同じ内容をお伝えしましたが、今日は Write が対象です。** 原文です。

> Fixed Read garbling UTF-16LE files with a byte-order mark, and Write dropping byte-order marks or silently converting Windows-1252, Shift-JIS, GBK or UTF-16BE files to UTF-8 (now refused)

2つの問題が直りました。

1. **Read が、BOM（バイト順マーク、ファイル先頭の文字コード識別子）付きの UTF-16LE ファイルを文字化けさせていた**
2. **Write が、BOM を落としたり、Windows-1252 / Shift-JIS / GBK / UTF-16BE のファイルを黙って UTF-8 に変換していた。今は拒否される**

Shift-JIS は日本語のファイルで広く使われている文字コードです。10月10日の修正（Edit / NotebookEdit）と合わせて、**読み・書き・編集の3方向すべてで「壊すくらいなら触らない」形になった**ということになります。

気になるなら聞けること: 「自分が Claude に触らせてるファイルの文字コード、一度まとめて確認できる?」

### 予定タスク（Routine）に直接関わる修正が4件

原さんの環境に一番近い部分なので、まとめて並べます。

1. **夏時間が終わるときの「繰り返される1時間」の間に、予定タスクとループが毎ターン再発火する、または早く発火していた**。日本は夏時間を使いませんが、**セッションのタイムゾーン設定次第で影響する可能性があります**
2. **予定タスクが「間違った分」として案内されていた**。スケジュール系のツールが、各ジョブの実際の次回実行時刻を報告するようになりました
3. **`ScheduleWakeup`（起床予定）が、バックグラウンドのタスクが動いている間は発火していなかった**（Agent SDK、IDE、`claude remote-control` のセッション）
4. **保存されたRoutine（ルーチン）を編集して保存すると、元の環境が削除されていた／一覧に無かった場合に、黙って別の環境に移されていた**。今はその環境を保持します（クラウドセッション）

### 情報が漏れる経路の修正が5件

今日は「本来送られるべきでない先に、資格情報や秘密が届いていた」という系統が多いので、まとめます。

1. **サーバー管理の設定を取得するリクエストが、Anthropic に対して、第三者ゲートウェイの APIキーを載せて送られていた**（管理設定ファイルが `ANTHROPIC_BASE_URL` を設定している場合）
2. **機能フラグ・起動時・高速モード・プロファイル・フィードバックの各リクエストが、第三者ゲートウェイ用に設定された APIキーを載せて Anthropic に送られていた**（Anthropic の APIキーは引き続き送られます）
3. **説明なしで起動したエージェントのチームメイトが、プロンプトに含まれていた資格情報の一部を、表示されるタスクの説明に残していた**
4. **サンドボックス内のシェルコマンドが、`--plugin-dir` のフォルダに書き込めた。** そのフォルダのコードは Claude Code が**サンドボックスの外で**再読み込みして実行します
5. **macOS のサンドボックス内のコマンドが、拒否されたパスがシンボリックリンクを経由している場合に、その実体の場所を指定して読み書きできた**

4番目と5番目は「サンドボックス（隔離された実行環境）から外に出られる」系統です。

### plan モードで、フックが許可した書き込みが実行されていた

**plan モード**（計画を立てるだけで変更を加えないモード）で、**`PreToolUse` フックや Mod の `tool.check` フックが許可した書き込み**（MCP ツールの書き込み、ファイルの書き込み、シェルコマンド）が、**実際に実行されていた**のが直りました。

plan モードは「何も変更しない」という前提のモードなので、その前提が崩れていたことになります。

あわせて、**bypass permissions が利用可能な状況では、plan モードがほとんどの編集やコマンドの前に確認しない**ことを伝える1回限りの注意書きが追加されました。

### フックやガードをすり抜ける穴が4件

- **Mod のフックに渡される値から `__proto__` キーが黙って削除されていた**。これにより、別の Mod が行ったツール呼び出しで `tool.check` のガードが飛ばされる可能性がありました
- **プラグインのフックが、非常に深く入れ子になったツール入力やメッセージを `next()` で渡すと、飛ばされていた**
- **Windows で、シェルを指定していない `PreToolUse` と `PermissionRequest` フックが、Git for Windows が入っていないと「通す」方向で失敗していた**。今は失敗したガードは呼び出しをブロックします
- **利用者が入れた Mod の `$.env.set` が、管理設定由来のコマンド型フックが起動する環境やシェルの前置きを変更できていた**

あわせて、**管理された許可ルール・管理されたフック・組織の MCP ツール名の、利用者が入れた Mod に対する強制が改善**されました。

### `rm` の確認プロンプトの出し方が変わりました

今週ずっと続いていた `rm` 系の話ですが、今日は**逆方向**の変更です。

**`rm` を実行しないシェルの `-c` スクリプトに対して、`rm` の確認プロンプトが出ていた**のが直りました。**Claude Code が読めないスクリプトの中で実行時に組み立てられる `rm` は、`CLAUDE_CODE_STRICT_INLINE_SHELL_RM_PROMPT=1` を設定しない限り、確認を求めなくなります。**

10/2 から 10/10 まで「保護が外れる穴」が続いていましたが、その対策で**確認が出すぎるようになっていた分を戻した**、という読み方ができます。設定で元の厳しい挙動に戻せます。

### Platform に OpenTelemetry エクスポート（beta）が入りました

**OpenTelemetry** は、アプリの動作を追跡・計測するためのデータ形式の標準規格です。

**Messages API のリクエストと Claude Managed Agents のセッションを、自分の監視システムで追跡できる**ようになりました（beta）。

- **Claude SDK が、Python / TypeScript / C# / Go / Java / PHP / Ruby でスパン（追跡の単位）を出します**
- **API からスパンを受け取るには、Claude Console で OpenTelemetry の送信先を追加**します

ドキュメントに18ページが新設されています。送信先を管理する API（`telemetry_destinations` の作成・削除・一覧・取得・テスト・更新、ワークスペースへの追加・一覧・削除）、`api/opentelemetry/spans`、`manage-claude/opentelemetry` の3ページです。

Claude Code 側でも、OpenTelemetry の出力が強化されました（④に記載）。

### Managed Agents の「安全な配備」のドキュメントが3ページ新設

`managed-agents/secure-deployment`、`secure-deployment-risks`、`secure-deployment-monitoring` の3ページが追加されました。内容は今日の目次からは分かりません。

### 価格表の計算例が Opus 5 から Opus 5.5 に差し替えられました

**価格そのものの変更ではありません。** 価格表の「1時間のコーディングセッションの費用」という計算例が、Claude Opus 5 ではなく **Claude Opus 5.5** を使う形に書き換わりました。

| | 旧（Opus 5） | 新（Opus 5.5） |
|---|---|---|
| 入力 5万トークン | 50,000 × $5 = $0.25 | 50,000 × $4 = $0.20 |
| 出力 1.5万トークン | 15,000 × $25 = $0.375 | 15,000 × $20 = $0.30 |
| セッション稼働 1時間 | $0.08 | $0.08 |
| **合計** | **$0.705** | **$0.58** |

キャッシュを使った場合の例も同様に差し替えられ、**$0.525 → $0.428** になっています（キャッシュ読み取りの倍率も 0.1 → 0.05 に変わっています。これは Opus 5.5 の料率です）。

**原さんの使用モデルは Claude Opus 5 で、その価格は変わっていません。** 入力 $5 / 出力 $25 / キャッシュ読み取り $0.50 のままです。**例に使われるモデルが新しい世代に移っただけ**です。

あわせて、支払い方法の説明に **Claude Console の Billing ページ（`platform.claude.com/settings/billing`）へのリンク**が追加されました。

### 新機能・追加

- `CLAUDE_CODE_DISABLE_FILE_MENTIONS` を追加。`@` のファイル言及について、Claude がファイルの中身ではなく**パスを受け取り、自分のファイルツールで読む**ようになる
- `/effort` と `/fast` をエージェント画面に追加（新しいセッションの初期値を設定する）。そこで `/model`・`/effort`・`/fast` を引数なしで打つと選択画面が開く
- `--safe-mode` で起動したバックグラウンドセッションの、エージェント画面の覗き見パネルに「safe mode」の行を追加
- `--disallow-tools` と、ケースごとの `disallowed_tools` フィールドを `claude plugin eval` に追加（Agent などの内蔵ツールを評価の実行から外せる）
- `--shutdown-drain-sec` を `claude self-hosted-runner orchestrator` に追加（SIGTERM で polling を止め、実行中の poll と spawn フックに指定秒数まで猶予を与える）
- `/advisor` を Claude Platform on AWS で利用可能に。`/advisor`・`advisorModel`・`--advisor` で選ぶまでアドバイザーは動かず、`CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1` でオフになる
- Claude デスクトップアプリの Code タブで、帰属表示ブロックをオフにできるように（Claude apps gateway の `code` ポリシーの `env` に `CLAUDE_CODE_ATTRIBUTION_HEADER=0`）
- Claude apps gateway 配下の Claude Code セッションの帰属表示ブロックに項目を追加（`CLAUDE_CODE_ATTRIBUTION_HEADER=0` で削除可）
- `/usage` に、max effort・ワークフロー・常時オンのコンテキスト・大きなツール結果についての警告を追加
- `/plugin` と `claude plugin validate` に、組織が Claude Code を管理している環境で飛ばされる Mod のフックを名指しする注記を追加

### OpenTelemetry・計測
