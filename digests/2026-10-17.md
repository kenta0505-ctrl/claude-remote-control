## ② ⚠️ 今の使い方が変わるもの

### 1.【訂正】Fast mode のレート上限の対象が、Anthropic 側で書き換わりました

昨日（10/16）のダイジェストの②で、こう書きました。

> **レート上限** | — | **全ての利用段階に既定の上限が付きました**

**Platform リリースノートの同じ項目が、今日の取得で書き換わっていました。** 原文の変化です。

- 旧: 「Claude Opus 5.5 now has a default fast mode rate limit in **every usage tier**」（**全ての利用段階**に既定の Fast mode レート上限が付いた）
- 新: 「Claude Opus 5.5 now has a default fast mode rate limit in the **Start, Build, and Scale** usage tiers」（**Start / Build / Scale の利用段階**に既定の Fast mode レート上限が付いた）

つまり **「全ての段階」ではなく、名前の挙がった3段階だけ**です。それ以外の段階（上位の段階など）については、今日の資料に記述がありません。

私が昨日書いた内容は、その時点のリリースノートの通りでしたが、**今は正確ではありません。** 訂正します。

### 2. 単独版の Claude Design が、2026年12月14日に閉鎖されます

Claude Code の `/design-sync` と `/design-login` に、**「単独版の Claude Design（claude.ai/design）は 2026年12月14日までに閉鎖される」** という通知が追加されました。

あわせて、`/design consent` と `/design revoke` が、クラウドセッションで失敗したときに `/design-login`（クラウドセッションでは使えません）を提案していたのが直り、**`claude.ai/design/settings` を案内する**ようになりました。

これは **日付の付いたサービス終了の告知**です。原さんが claude.ai/design を使っているかは PROFILE.md に記載がないので判断できませんが、使っている場合は12月14日までに移行が必要になります。

気になるなら聞けること: 「自分が claude.ai/design を使ってるかどうか、確認できる?」

### 3. `claude -p` と Agent SDK の初期パーミッションモードが変わりました

**パーミッションモードを指定していない `claude -p` と Agent SDK のセッション**が、以下の条件で **`default` モードで開始**するようになりました。

- 第三者プロバイダ（Bedrock、Vertex など）を使っている
- テレメトリ（利用状況の送信）をオフにしている
- または新規インストール

**`--permission-mode auto` を明示すれば、auto モードは維持されます。**

### 4. fork サブエージェントが、既定でオンになりました

**fork サブエージェント（`subagent_type: "fork"`）** が、**`claude -p`・Agent SDK・デスクトップアプリ・VS Code で既定でオン**になりました（ターミナルでは既にオンでした）。

- **オフにするには `CLAUDE_CODE_FORK_SUBAGENT=0`**
- **`claude mcp serve` では提供されません**

### 5. サブエージェントの動く場所が変わりました

- **デスクトップアプリと VS Code が、本体の会話のサブエージェントを常にバックグラウンドで動かす**ようになりました（ターミナルと同じ挙動。これまでは Claude が選んでいました）
- 逆に、**サブエージェント自身が呼ぶ Agent の呼び出しは、`claude -p`・Agent SDK・デスクトップアプリ・VS Code で既定で前面で動く**ようになりました

### 6. その他の挙動変更

- **`CLAUDE_CODE_AUTO_MODE_MODEL`** を追加。auto モードの**手元の分類器**が使うモデルを選べます。**サーバー側の auto モードのモデルは変わりません**
- **`/config` に「Idle compaction」の行**が追加されました（10月15日に入ったアイドル圧縮のオン・オフ）。圧縮の後に出る通知も、**オフにする方法を伝える**ようになりました
- **プロンプトとエージェントのフックが、同じイベントについて同時に最大12個まで**走るよう変更。残りは順番を待ちます
- **`← for agents` のフッターのヒントが、セッションを開いて10秒後に消える**ように変更（待っているエージェントの件数は引き続き表示されます）
- **組織のポリシーが `/feedback` をオフにしているときのメッセージ**が、組織の管理者ではなく **GitHub の issue を案内する**ように変更
- **Claude in Chrome の指示文がシステムプロンプトの中で置かれる場所が変わりました。** 新しい会話が共有のプロンプトキャッシュから読めるようにするためです

## ③ 今日の変更（説明つき）

### Routine が途中で失敗すると、1時間以上あとに最初からやり直され、作業が重複していた

**原さんの環境に一番近い項目です。** 原文です。

> Fixed a scheduled routine run that failed partway being run again from the start an hour or more later, which could repeat work such as posting the same report twice

**予定された Routine の実行が途中で失敗すると、1時間以上あとに最初からやり直されていた**のが直りました。CHANGELOG が挙げている具体例が **「同じ報告を2回投稿する」** です。

この digest セッションのような「毎朝1回、報告を出す」Routine が、まさにこの条件に当たります。

**ただし原さんの Routine については、これまで同じダイジェストが2回出たことはありません**（この会話の履歴で確認できます）。該当していなかった、または失敗が起きていなかった、ということになります。

気になるなら聞けること: 「過去に同じ内容が2回届いてた日がないか、確認できる?」

### MCP のプロトコル 2026-07-28 で、ツールが一つも出ない・全部失敗する不具合

10月8日から今週ずっと「MCP のプロトコル交渉の既定が 2026-07-28 になる」という変更をお伝えしてきました。その**新しいプロトコルで動かないケース**が直りました。

**サーバーがプロトコル 2026-07-28 を交渉したうえで、`resultType`・`ttlMs`・`cacheScope` のいずれかを省略すると、そのサーバーのツールが一つも表示されない、またはツール呼び出しが全部失敗していました。**

原さんのコネクタ（Square / Gmail / Google Drive / Google Calendar）は、クラウドセッション側で10月15日からこの新しいプロトコルが既定になっています。**「繋がっているのに何もできない」という症状が出ていた場合、これが原因だった可能性があります。**

### auto モードの安全性チェックが、会話が長すぎると全部拒否していた

**サーバー側の分類器を使う auto モードで、安全性チェックに対して会話が長すぎる場合**、これまでは **検査対象のツール呼び出しが全部拒否されていました**。今は **会話が圧縮される**ようになりました。

10月3日に「手元の分類器」について同じ修正をお伝えしましたが、今日は **サーバー側の分類器**についての同じ対処です。

### Read ツールが、巨大な画像ファイルを丸ごとメモリに読み込んでいた

**Read ツールが、どんなサイズの画像ファイルでも、あるいは画像のような名前のパイプやデバイスでも、丸ごとメモリに読み込んでいた**のが直りました。

**今は 128 MB を超える画像ソースは拒否されます。**

10月16日の「バイナリファイルをテキストとして読んでいた」に続く、Read ツールの入力検証の修正です。

### Windows の exFAT / FAT32 ドライブで、すべてのファイル書き込みが拒否されていた

**exFAT または FAT32 のドライブ上のプロジェクトで、すべてのファイル書き込みが拒否される、または確認を求められていた**のが直りました。`--plugin-dir` で起動したセッションも含みます。

exFAT と FAT32 は、USB メモリや外付けドライブでよく使われる形式です。

### プロンプトの候補が、クレジットを消費していた

**プロンプトの候補（入力欄に出る提案）が、プランではクレジット払いでしか使えないモデルで、使用枠のクレジットを消費していた**のが直りました。**今は、クレジットに請求された返答の後は候補の生成が飛ばされます。**

意図せずクレジットが減っていた、という種類の修正です。

### 多数のプラグインを有効にしている環境の起動が速くなりました

**プラグインのコマンドとエージェントのファイルの読み込みに必要なファイルシステムの呼び出しが、大幅に減りました。** 特に Windows で効きます。

### CMEK のドキュメントが1ページ新設

昨日「`/claude-api` スキルが、CMEK（顧客管理の暗号鍵）の外部鍵エンドポイントが Claude Platform on AWS で使えないと言っていたのを修正」とお伝えしましたが、今日は **`manage-claude/cmek-claude-platform-on-aws` のページが新設**されました。昨日の修正と対応する動きです。
