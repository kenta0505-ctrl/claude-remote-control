## ② ⚠️ 今の使い方が変わるもの

価格の変更とモデルの廃止予告はありません。挙動が変わるものを並べます。

### 1. しばらく使っていない会話の再開に、警告が出るようになりました

**Pro と Max プランで、使っていなかった会話を再開しようとしたとき、それが5時間の使用上限のかなりの割合を消費する場合に警告**が出るようになりました。

選べるのは2つです。

- **そのまま再開する**
- **新しい会話を始める。** その場合でも、**以前の会話について触れれば Claude が調べられる**、と説明されます

長く放置した会話を開くと、その履歴をもう一度読み込むぶんだけ使用枠を使う、という性質に対する注意喚起です。

### 2. 自分でペースを決める `/loop` の起床予定の、発火タイミングが直りました

**1時間の上限いっぱいに設定した自分でペースを決める `/loop` の起床予定が、1時間のプロンプトキャッシュが切れた直後に発火していた**のが直りました。**その結果、起床した会話をキャッシュなしで読み直していました。**

キャッシュが効いていれば読み直しの費用は10分の1（Opus 5 の場合）ですが、切れた直後だと全額かかります。**「1時間ちょうど」に設定していた場合、毎回全額を払っていた**ということになります。

10月15日に入ったアイドル圧縮（20万トークン超の会話を約54分で圧縮する）と同じ、「1時間キャッシュの期限に間に合わせる」系統の修正です。

### 3. ツール検索が、カスタム `ANTHROPIC_BASE_URL` 配下で既定でオンに

**カスタム `ANTHROPIC_BASE_URL`（自前のゲートウェイ）を使っている環境で、ツール検索が既定でオン**になりました。**ゲートウェイが 400 または 422 を返した場合は、ツール検索なしで再試行されます。**

### 4. 圧縮の後のスキル一覧の扱いが変わりました

- **圧縮（会話の要約圧縮）の後、Claude にスキルの一覧が再送される**ようになりました
- それに伴い、**`/reload-skills` は新しい・変わったスキルだけを送る**ようになりました（これまでは全部でした）

10月16日に「`/reload-skills` の説明を改善（圧縮後にスキルを戻す方法であることを明記）」とお伝えしましたが、**今日は圧縮後の再送が自動になった**ので、手動で `/reload-skills` を打つ必要が減ったことになります。

### 5. スキルのフックに上限が付きました

**1つの出どころ（リポジトリ、自分のフォルダ、プラグイン）のスキルが登録できるのは、1セッションあたり最大 1,024個のフックと、16,384文字のマッチャー**までになりました。

あわせて、**プラグイン由来のフックだけを許可するポリシーの下では、本体の会話で使われたスキルのフックが除外される場合、そのスキルの `allowed-tools` も適用されなくなりました。**

### 6. `CLAUDE_CODE_AUTO_COMPACT_WINDOW` の単位の扱いが直りました

**`CLAUDE_CODE_AUTO_COMPACT_WINDOW=200k` が、黙って 100K の窓を設定していた**のが直りました。

- **`k` と `M` の接尾辞を受け付ける**ようになりました（`--autocompact` と同じ）
- **範囲外の値や無視される値には警告が出る**ようになりました

「200k と書いたのに 100K になっていた」という、設定した本人には気づけない種類の不具合でした。

### 7. その他の挙動変更

- **`/artifacts` の削除確認が、番号付きの選択肢**になりました。**1 または Enter で保持、2 で削除**。`y`・`n`・Esc も引き続き使えます
- Mod の `settings.read` フックが、**設定の各層を受け取り、統合後の設定を書き換える**ようになりました。**管理された Mod が、組織の設定を上限として扱える**ようになります（保持期間の整理が使う `cleanupPeriodDays` を含む）
- `/fast` のダイアログのタイトルから **「(research preview)」のラベルが Opus 5.5 で削除**されました（10月16日の Fast mode の研究プレビュー終了に対応）
- `/claude-api` スキルが、Claude Platform on AWS で SDK や curl に落ちる代わりに **`ant` CLI を使う**よう更新
- `claude plugin validate` から、**Mod のフックがどこで走るかを予測する注記が削除**されました

（継続中のものを再掲します。**単独版の Claude Design が 2026年12月14日に閉鎖**されます。**Claude Sonnet 4.5 が 2026年11月30日に API から停止**します。原さんの使用モデルは Claude Opus 5 なので後者の直接の影響はありません。）

## ③ 今日の変更（説明つき）

### `rm -r` の安全確認の穴が、また1件

今週ずっと続いている系統です。原文です。

> Fixed `rm -r` of a mounted drive or a folder at its top level (`/Volumes`, `/media`, WSL's `/mnt/c`) not getting the safety prompt that `rm -rf /Applications` gets

**マウントしたドライブ、またはその直下のフォルダ**（macOS の `/Volumes`、Linux の `/media`、WSL の `/mnt/c`）に対する `rm -r` が、**`rm -rf /Applications` には出る安全確認のプロンプトを受けていなかった**のが直りました。

**`/mnt/c` は、WSL から見た Windows の C ドライブそのもの**です。つまり WSL 環境では、**Windows 側のドライブ全体を削除するコマンドに確認が出ていなかった**ことになります。

この系統の記録です。

- 10/2: 出力リダイレクトと組み合わせると保護が外れる
- 10/3: `bash -c` の中に書くと外れる
- 10/5: 環境変数の前置きなど5件
- 10/7: Windows の 8.3形式の短い名前で指すと外れる
- 10/10: Git Bash での `/c/Users/<名前>` 表記で外れる
- 10/15: `rm` を実行しないスクリプトに確認が出すぎていた分を戻す（逆方向）
- **10/20（今日）: マウントしたドライブとその直下のフォルダで外れる**

### `claude --worktree` が、確認なしに worktree とブランチを削除していた

**`claude --worktree` が、終了時に、HEAD が切り離されている場合や別のブランチにいる場合に、確認なしで worktree とそのブランチを削除していた**のが直りました。**コミットが失われうる**状況でした。

10月16日に「`WorktreeCreate` フックが作った worktree が、push していないコミットを含んでいる可能性があるのに確認なしで削除されていた」とお伝えしましたが、**今日は `--worktree` で起動した場合の別のケース**です。4日で2件目になります。

### Cowork のクラウドセッションの Routine が、サブエージェントごとに5分待っていた

**予定された Cowork のクラウドセッションが、WebFetch で URL の承認が必要になったサブエージェントごとに、また5分待っていた**のが直りました。**誰も答える人がいない状況で**です。

10月9日に「Cowork のクラウドセッションが、未承認 URL への WebFetch の許可プロンプトが5分間放置されたあと『入力待ち』のまま残っていた」とお伝えしましたが、**今日はサブエージェントごとに繰り返し待っていた分**です。

Routine の実行が無駄に長くなる種類の不具合です。

### Code Review にレビューの深さの選択が追加されました

**レビューレベル（review levels）** が追加されました。

- **オーナーが組織全体に対して Quick / Standard / Deep のいずれかを選びます**
- **既定は Standard** です
- **個別のリポジトリに独自のレベルを与える**こともできます

あわせて、**GitHub 組織の全リポジトリをレビュー対象にする選択肢**が管理設定に追加されました。**後から追加されたリポジトリも含まれ**、1つずつ選ぶ必要がなくなります。

また、**管理者が Code Review を有効にしてから1〜2分以内に開かれたプルリクエストが、黙って飛ばされていた**のが直りました（今は再試行されてレビューされます）。

### auto モードの設定を手伝うコマンドが、対応環境を広げました

**`/auto-mode-setup`** が追加されました。**プロジェクトと最近のセッションを読んで、auto モードに自分の環境のことを教える、案内付きの設定**です。

対応が広がった先が明記されています: **Bedrock、Vertex、Foundry、Claude apps gateway、テレメトリをオフにしたセッション**。

### Managed Agents の設定を、公開されている安全指針と比べるコマンド

**`/claude-api managed-agents-secure`** が追加されました。**Managed Agents のエージェントの設定を、Anthropic が公開している安全指針（security guide）と比較**します。**何も変更しません。**

10月15日に Managed Agents の `secure-deployment` のドキュメントが3ページ新設されたことをお伝えしましたが、それに対応するコマンドです。

### セッション記録のサイズと、長い会話のメモリ使用量が改善

3件まとめます。

- **auto モードのセッションファイルのサイズを改善**: 安全性分類器の文脈が、**毎リクエストごとに保存されなくなりました**
- **長い会話・再開した会話でリクエストを送るときのメモリ使用量を改善**
- **多数のサブエージェントが同時に動いているときの応答性とスループットを改善**

### Mod の `tool.check` に「人にしか答えさせない」選択肢が追加

Mod が、ツール呼び出しの許可を判定する `tool.check` の答えとして **`decider: "person"`** を返せるようになりました。

- **許可ダイアログ、またはホストのコールバックだけがその確認を承認できます**
- **誰にも尋ねられない状況では、その Mod が示した理由とともに拒否されます**

あわせて、**`e.isReadOnly`**（そのツール呼び出しが読み取り専用かどうか）も受け取れるようになりました。

## ④ 一行で流すもの

### 許可・サンドボックス・セキュリティ

- サンドボックス内のコマンドが Linux で起動に失敗していたのを修正（`sandbox.filesystem.denyRead` の glob に、文字クラスではない角括弧が含まれる場合。`[user-id]` のようなルーティング用フォルダなど）
- `PreToolUse` フックの拒否理由が、同じツール呼び出しに対する Agent SDK のコールバックフックがタイムアウトすると、タイムアウトエラーに置き換えられていたのを修正
- プラグインが、サブエージェントを起動する・終了したものを再実行することで、`--max-turns`・Stop・入力の終了を越えてヘッドレスの実行を続けさせていたのを修正
- 組織のポリシーが、起動時に `ANTHROPIC_API_KEY` を承認した後、または `/config` で「Use custom API key」を切り替えた後、**次の毎時の確認まで更新されていなかった**のを修正
- Consumer Terms（消費者向け規約）の通知が、サーバーエラーの後に1日以上飛ばされていたのを修正
- `/privacy-settings` が、ネットワークやサーバーのエラーの後に、該当しない可能性のある選択肢を提示していたのを修正

### 圧縮・コンテキスト・モデル

- ターンを止めたときに「Context limit reached」や「Prompt is too long」エラーが出ていたのを修正（API が長すぎると拒否した会話を Claude Code が圧縮している最中だった場合）
- モデルの切り替え・メッセージ・中断が、SDK とデスクトップのセッションで、**コンテキスト使用量の確認の後ろで待たされていた**のを修正
- LLM ゲートウェイ配下で `context_management: Extra inputs are not permitted` エラーが出ていたのを修正（今はその項目を外して再送する）
- 再開したセッションとクラウドセッションが、起動時にプラグインが再読み込みされるたびに、**スキルの一覧全部を Claude に送り直していた**のを修正
- SDK とヘッドレスのモードで、大きく圧縮されたセッションの再開を改善（再開後の最初のリクエストが早く送られる）
- `CLAUDE_CODE_TRANSCRIPT_LOCAL_GC` が、ファイルを切り詰めている最中にディスクが満杯になると、保存済みの記録からメッセージを落としていたのを修正

### サブエージェント・エージェント

- サブエージェントが、終了直後にメッセージを受けた・再開されたときに、**直近の作業を忘れることがあった**のを修正
- エージェントチームで、本体セッションからの停止要求を承認すると **CLI 全体が終了していた**のを修正
- 圧縮の要約に、**それまでに呼ばれたツールの名前**が記録ビュー（Ctrl+O）で表示されるようになりました

### Mods・プラグイン

- 先に走るプラグインが Mod のフックを飛ばしたとき、**イベント名とそのプラグイン名を記録に出す行**が追加されました
- Mod の再読み込みが失敗すると、**読み込まれたままの版のツールとコマンドが削除され**、以前の版がまだ読み込まれているかどうかについてのメッセージが誤っている・何も出ないことがあったのを修正
- Mod のボタンが、同じラベルで `key` を持たないボタンが変更なしで再描画されると、クリックが失われていたのを修正

- セッション内で書いた Mod が読み込まれる・再読み込みされる・失敗するときに表示される行を改善
- セッション内で Claude が書いた Mod を有効にするかの質問を、**リンクもセッションIDも無い平文**に変更。新しいターンが始まっても表示が残り、**有効にすると Claude が何が読み込まれたかを伝える**ようになりました
