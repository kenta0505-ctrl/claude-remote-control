Fast mode = Claude Opus の返答を速くする有料の設定です。

### 3. 作業フォルダの外への書き込みを禁止する設定が追加されました

> **`permissions.blockWritesOutsideWorkingDirectories` を追加**: **Write・Edit・NotebookEdit が、すべての権限モードで、作業ディレクトリの外のパスを拒否します**

**「すべての権限モードで」**と書かれています。**権限確認を飛ばすモードでも効く**ということです。

**あわせて、組織の設定ファイルを守る変更も入りました。**

> **Claude のファイルツール**を、**自分の設定ファイルに対してするのと同じように、組織のサーバー管理設定のローカルのコピーを編集する前に確認を求める**よう変更

### 4. 放置された会話の自動要約が、VS Code とデスクトップアプリに来ました

> **VS Code と Claude Desktop の Code タブにアイドル圧縮を追加**: **20万トークン以上の会話を放置すると要約され、プロンプトキャッシュが期限切れになっていれば、次のメッセージでその要約が使われます**

> **アイドル圧縮**を、**動作記録（telemetry）をオフにしている契約者でも、また Bedrock・Vertex・Foundry・LLM ゲートウェイでも、1時間のプロンプトキャッシュが有効になっていれば動く**よう変更

**「放置すると勝手に要約される」** 挙動なので、**長い会話を開いたまま離席すると、戻ったときに中身が要約されている**ことがあります。

### 5. クラウドセッションが、準備スクリプトのエラーでも起動するようになりました

> **[Cloud sessions] web・デスクトップ・モバイルのアプリからのクラウドセッション**を、**準備スクリプトがエラーで終了しても、起動に失敗せずに起動する**よう変更

**これまでは準備スクリプトが失敗するとセッションが始まりませんでした。今日から始まります。** **「準備が失敗したことに気づかないまま作業が進む」可能性がある**ので、裏返しの注意点として書いておきます。

### 6. `FORCE_HYPERLINK=false` が、逆の意味だったのが直りました

> **`FORCE_HYPERLINK=false`（`no` と `off` も）** を、**ハイパーリンクをオンにするのではなくオフにする**よう変更

**「オフにする」と書いたつもりの設定が、オンにしていた**という不具合です。**この設定を使っていた場合、今日から挙動が逆になります。**

### 7. Monitor ツールのコマンドにも、フックが掛かるようになりました

> **Bash に一致するフック**が、**Monitor ツールが起動したシェルのコマンドでも実行される**ようになりました。**そうしたフックは、それらのコマンドをブロックしたり確認を求めたりはできますが、承認したり書き換えたりはできません**

> **`Monitor(tail *)` のようなフックの `if` 条件**を、**`Bash(tail *)` が Bash のコマンドに一致するのと同じように、Monitor ツールのシェルのコマンドに一致する**よう変更

**これまで Monitor ツール経由のコマンドはフックをすり抜けていた**ということです。**止める側の設定が、今日から効き始めます。**

### 8. `--setting-sources` で除外した設定が、本当に除外されるようになりました

> **`--setting-sources` で除外した設定ファイル**が、**auto モードのルールと保存された権限の同意など、一部の設定を依然として提供していた**のを修正

**「この設定ファイルは使わない」と指定したのに、一部が効いていた**という不具合です。

### 9. その他、止める側の挙動が変わったもの

> - **`claude -p --resume` または `--continue` で入った worktree に、サンドボックスの保護が適用されていなかった**のを修正
> - **`/permissions` の Recently blocked** を、**全文が読めない呼び出し（端末が短くて表示しきれないものを含む）の承認を拒否する**よう変更
> - **Cowork のクラウドセッションの auto モード**を、**フックによる MCP ツール呼び出しの許可を「回答なし」として数え、分類器または権限の確認が判断する**よう変更
> - **`/ultrareview`** を、**`claude ultrareview` と同じように、git を実行する前にワークスペースの信頼を確認する**よう変更
> - **`claude ultrareview` と `claude remote-control`** が、**端末を持つ CI のジョブでワークスペースの信頼を質問していた**のを修正。**`CI` が設定されていれば、信頼されていないフォルダを即座に拒否します**
> - **auto モードが、安全性チェックが判定を返さなかったときに、呼び出しをブロックしたと報告し、`/permissions` に載せていた**のを修正
> - **auto モード・拒否ルール・PreToolUse フックがブロックした、あるいはその他の理由で実行されなかったシェルと MCP の呼び出しが、折り畳まれたツールのグループの中で、実行されたように読めていた**のを修正
> - **`sandbox.excludedCommands` の設定の説明**が、**列挙したコマンドは常にサンドボックスの外で実行されると言っていた**のを修正。**今後は「1回の呼び出しの中のすべてのコマンドが項目に一致しなければならない」と言います**

### 10. `which` の扱いが変わりました

> **Bash ツールのシェル**を、**継承した `which` のエイリアスや関数をクリアし、エクスポートされた `which` / `unsetenv` の関数をコマンドに渡すのをやめる**よう変更。**`which` がシステムのコマンドか zsh の組み込みコマンドになります**

**自分で `which` を上書きしていた場合、Claude Code の中では効かなくなります。**

### 11. 拒否されたときのモデル切り替えの挙動が変わりました

> **印の付いたリクエスト**を、**`ANTHROPIC_DEFAULT_OPUS_MODEL`・`availableModels`・`deniedModels` によって古い Opus のモデルしか、あるいは1つも残らない場合に、拒否で終わらせるのではなく別のモデルで再試行する**よう変更

### 12. macOS で `git grep` のロケールが変わりました

> **macOS: Claude が実行するほとんどのコマンドの `git grep`** を、**C ロケールを使う**よう変更。**有効な UTF-8 でないファイルに対する macOS の正規表現ライブラリのメモリリークの報告を避けるためです**

**日本語を含むファイルの検索結果が変わる可能性があります**（C ロケールは文字の扱いが単純になります）。

### 13. ゴミ箱フォルダの上限が決まりました

> **`~/.claude/skills/.trash` と `~/.claude/plugins/.trash` が無制限に増えていた**のを修正。**`cleanupPeriodDays` が何と言っていようと、それぞれ約1024件を保持します**

**`cleanupPeriodDays` を大きく設定していても、1024件で打ち切られる**ということです。

### 14. PreCompact フックの出力が10,000文字で切られるようになりました

> **出力が非常に大きい PreCompact のフックが、圧縮を失敗させたり繰り返させたりしていた**のを修正。**各フックの出力は今後10,000文字で切られます**

### 15. VS Code の Claude in Chrome の設定が変わりました

> **[VSCode] `CLAUDE_CODE_DISABLE_CFC_PROMPT`** を、**拡張機能がセッションのメッセージに Claude in Chrome の指示を追加するのも止める**よう変更。**ブラウザのツールは引き続き使えます**

（継続中のものを再掲します。**単独版の Claude Design が 2026年12月14日に閉鎖**されます。**API バージョン `2026-10-21` では `temperature` 等が全モデルで使えなくなります。** 原さんの使用モデルは Claude Opus 5 で、claude.ai 経由なので、いずれも直接の影響はありません。）

## ③ 今日の変更（説明つき）

### 組織が考える深さに上限をかけたとき、止まらずに下げて続くようになりました

> **組織の管理者がモデルの effort に上限をかけたときに、セッションが毎ターン「Invalid effort level」で失敗していた**のを修正。**Claude Code は今後、effort を下げて再試行し、どのレベルを使うかを言います**

effort = Claude がどれくらい深く考えるかの設定です。

**組織が「high まで」と決めたのに、Claude Code が xhigh で送り続けて、毎回失敗していた**という不具合です。**今回から、自分で下げて続けます。**

### 他社のゲートウェイやクラウド経由で、リクエストが通るようになりました（3件）

> - **ツール検索の `tool_reference` ブロックを受け付けないゲートウェイの背後で、リクエストが繰り返し拒否されていた**のを修正。**ツール検索なしで1回送り直し、セッションがそれを記憶します**
> - **ゲートウェイやクラウドのプロバイダが、Claude Code のベータヘッダのどれかを名前を挙げて拒否したときに、リクエストが失敗していた**のを修正。**それを外して送り直します**
> - **`claude-opus-4.8` のようにドットで綴られたモデル ID がゲートウェイの背後で使われたときに、古いモデルとして扱われ、コンテキスト幅・出力上限・effort・思考モード・費用が間違っていた**のを修正

**3つ目は特に影響が大きい種類**です。**間違ったモデルとして扱われると、費用の見積もりまでずれます。**

**Bedrock と Foundry についても修正があります。**

> - **画像が多い Bedrock のセッションが、古い画像を外して圧縮するのではなく、毎ターンと `/compact` で「400 Input is too long.」で失敗していた**のを修正
> - **Microsoft Foundry のセッションが、そのリソースに既定の Sonnet・Opus・Haiku のモデルのデプロイがないときに失敗していた**のを修正。**Claude Code は今後、その系列の古いモデルにフォールバックします**

### TLS の証明書の更新で接続できなくなる問題が直りました

> **システムの証明書ストアが、前任の証明書と相互署名された更新済みのルート証明書を保持しているときに、TLS 接続が `UNABLE_TO_GET_ISSUER_CERT` で失敗していた**のを修正

**証明書の更新のつなぎ目で、接続が全部できなくなる**という種類の不具合です。

**管理者の設定についても1件あります。**

> **管理者の TLS の信頼の設定が、管理された設定の中で、Claude Desktop のセッションに適用されていなかった**のを修正

### 「使用量の上限で自動的に続ける」が、3回を超えて勝手に続いていた不具合が直りました

> **「Continue automatically at usage limit」**が、**タスクが待機の合間に自分自身を再起動したとき（`/goal` のチェックイン、バックグラウンドまたはスケジュールされたタスク）に、あなたの指示なしに3回を超えて続けていた**のを修正

**「3回まで」という上限が、タスクが自分で再起動すると回数がリセットされていた**ということです。

### リポジトリのロックを奪い合って git が失敗する不具合が直りました

> **バックグラウンドの差分の更新が、リポジトリのインデックスのロックを短時間取っていた**のを修正。**同じ瞬間に実行された git のコマンドが「Unable to create '.git/index.lock': File exists」で失敗しうるものでした**

**Claude Code が裏で差分を見ている最中に、自分で git を叩くと失敗する**という形の不具合です。

### Claude が「止めたコマンドは実行されたかもしれない」と知るようになりました

> **クラウドセッションや IDE で Esc または Stop でコマンドを止めたときに、Claude には「拒否された」としか伝えられていなかった**のを修正。**今後は「そのコマンドは実行されたかもしれない」とも伝えられます**

**止めたつもりでも、すでに実行が始まっていた可能性がある**ことを、Claude が知らなかった、という点が重要です。**知らないと、Claude は「実行されていない」前提で次を考えてしまいます。**

### PDF の長い本文が黙って切られていた不具合が直りました

> **Cowork のクラウドセッションの WebFetch が、PDF のテキストの10万文字を超える分を黙って落としていた**のを修正。**今後は、どれだけ読まれなかったかと、続きをどこから読めばよいかを言います**

**「黙って落としていた」**のが問題でした。**Claude は全部読んだつもりで答えていた**ことになります。

### スケジュールされたタスクが、claude.ai のプラグインを読むようになりました

> **[Cloud sessions] スケジュールされたタスクを改善**: **Anthropic のクラウドでの実行が、claude.ai のアカウントで有効にしているプラグインを読み込む**ようになりました

**このダイジェストもスケジュールされたタスクです。** 今回から、**claude.ai で有効にしているプラグインが、こうした自動実行にも読み込まれます。**

### Claude Tag API のリファレンスが、まとめて公開されました

**Platform のドキュメントが 826 → 845ページ（+19）**に増えました。**増えた19ページは全部 Claude Tag API のリファレンス**です。

- **Slack ワークスペース**: `slack_workspaces`、一覧・取得・更新
- **Slack チャンネル**: `slack_channels`、一覧・取得・設定・更新・削除
- **バンドル**: `bundles`、一覧・取得、`bundles/targets`（一覧・取得・取り付け・取り外し）
- **入口**: `api/beta/organization/claude_tag`

**1週間前（10月23日付）に「Claude Tag API を beta 公開」と報告しました。** そのときは案内のページだけで、**今日ようやく API の詳細なリファレンスが揃いました。**

## ④ 一行で流すもの

**Claude Code 2.1.314 のうち、②③で触れていない残り（約70項目）**

追加

- **Claude アプリのゲートウェイの upstream に、任意の `groups` 一覧を追加。** **一覧された IdP（外部のサインイン提供元）のグループに属する開発者だけが、その upstream に送られます。フェイルオーバー時も同様です**
- **Claude アプリのゲートウェイの Bedrock の upstream に `guardrail_trace` を追加。** **どの Amazon Bedrock のガードレールのフィルタが反応したかを、一致したテキストなしで記録します**
- **[Cloud sessions] 完了した1回限りのタスクだけが隠れているとき、Scheduled tasks のページに「Include completed」ボタンを追加。** Sort メニューを開かずに表示できます
- **[Claude Tag] Slack を接続している Enterprise 組織の管理設定の Bundles と Channels のタブに、Claude Tag API のドキュメントへの、閉じられるリンクを追加**

修正

- **`claude -p` が、起動の失敗時に終了コード 0 で何も出力せずに終了していた**のを修正。**エラーを表示して 1 で終了します**
