## ② ⚠️ 今の使い方が変わるもの

### 1. IP アドレスによるアクセス制限が使えるようになりました（beta）

**11月5日付のリリースノートです。**

> **Claude Console で組織の IP 許可リストを設定できるようになりました（beta）。** **対象のサービスへのリクエストが、リストにないアドレスから来た場合は拒否されます。** **これにより、漏れた API キーが使える場所が限られます。** **IPv4 と IPv6 のアドレス、または CIDR の範囲を、1組織あたり最大1,000件まで追加できます。**

**ドキュメントの本文も取得して読みました。** 以下はすべてそのページからの引用です。

**⚠️ ここが最も重要です。** ドキュメントが「自分を締め出さないために」という節を立てて、こう書いています。

> **保存するとき、設定のページは、あなたが自分を締め出そうとしていないかを確かめるために、あなたの現在のアドレスをリストと照合します。** **しかし、あなたのサーバー、同僚、あるいは明日あなたが接続するかもしれないアドレスは確認しません。**
>
> **最初にすべてのネットワークを必ず列挙してください**: **データセンター、CI のシステム、オフィス、VPN、プロキシ、そして自前のサンドボックスのワーカーを、その公開の IPv4 と IPv6 のアドレスとともに含めてください。** **家庭と携帯のアドレスは、予告なく変わりうることに注意してください**
>
> **戻る道を確保してください**: **「管理者がこの設定ページに任意の IP アドレスからアクセスできるようにする」（Claude Console）または「オーナーが…」（claude.ai）のチェックボックスを選択することを、Anthropic は推奨します。** **そうすれば管理者（claude.ai ではオーナー）がどこからでもリストを直せます。** **欠点は、管理者やオーナーのセッションを侵害した攻撃者が、遠隔から許可リストを更新しうることです**

**締め出された場合の手順**も書かれています。

> 1. **許可されたネットワークから再接続する**
> 2. **別の管理者またはオーナーに頼む**
> 3. **上記のチェックボックスが選択されていれば、今いる場所からリストを直す**
> 4. **Anthropic に連絡する**: **管理者もオーナーも誰もページに到達できない場合は、Anthropic のサポートに許可リストをオフにするよう依頼してください**

**何が対象になるか**（Claude Platform の組織）

- **Claude Console の画面**
- **Claude API のエンドポイント**: Messages、Message Batches、Token Counting、Models、Files、Skills（API キーまたは Workload Identity Federation のトークンを使う場合）
- **Claude Managed Agents のエンドポイント**: Agents、Sessions、Environments、Vaults、Memory stores（同様）
- **組織の API**: Admin API と Compliance API（**その組織だけを対象とする鍵**を使う場合）

**何が対象になるか**（Claude Enterprise の組織。**claude.ai 側は別の許可リストを持ちます**）

- **ブラウザの Claude、デスクトップアプリ、モバイルアプリ**
- **Claude Code**（Claude のアカウントでサインインする場合）
- **Claude in Chrome、Office のアドイン、Cowork、Remote Tools**
- **これらのアプリの中のコネクタと artifact**（**組織の外に共有された artifact は除く**）
- **Admin API と Compliance API**（その組織だけを対象とする鍵を使う場合）

**対象にならないもの**（ドキュメントの「Limitations」から）

> **Claude Platform**: **許可リストは Claude Managed Agents のエンドポイントへのリクエストを対象としますが、エージェントそのものは対象としません。** **Claude Managed Agents の実行環境の通信には適用されません。** **Claude in Amazon Bedrock、Claude Platform on AWS、Claude Models on Google Cloud、Claude in Microsoft Foundry には適用されません。**
>
> **Claude Enterprise**: **Claude Design、Claude in Slack、Claude Academy は対象外です。** **ユーザーが遮断されたときに Claude がチャットで作業中だった場合、その作業は最大24時間続きうります。** **そのユーザーは、リストの外からそのチャットを開いたり操作したりできません。**

**拒否されたときに何が起きるか**

- **API**: **403 の `permission_error`** で、メッセージは **`Your IP address isn't in this organization's allowed range.`**
- **人**: **「Your current network can't access this organization」という題のページ**が表示されます
- **Claude Code**: **同じメッセージの 403 の API エラー**

**設定の形式と反映時間**

| 項目 | 内容 |
|---|---|
| 形式 | **IPv4 または IPv6 の単一アドレス（`203.0.113.5`）、または CIDR の範囲（`203.0.113.0/24`、`2001:db8::/32`）** |
| 範囲の上限 | **IPv4 は `/8` より広くできない。IPv6 は `/32` より広くできない** |
| 件数の上限 | **1,000件** |
| 公開アドレスのみ | **`10.0.0.0/8` のような私的な範囲ではなく、通信が自分のネットワークを出ていくアドレスを列挙する** |
| **反映時間** | **最大15分**（**Claude Enterprise では、すでに開いている接続・Office のアドイン・Remote Tools への反映にさらに時間がかかりうる**） |
| 設定場所（Platform） | Claude Console の **Identity and access** のページ |
| 設定場所（Enterprise） | claude.ai > **Organization settings > Organization and access** |

**ドキュメントが添えている注意**も書いておきます。

> **許可リストは鍵が働く場所を限りますが、どれだけの期間働くかは限りません。** **短い鍵の有効期限も設定するか、静的な鍵を使うのをやめて Workload Identity Federation に移行してください。** **これは許可リストだけよりも安全です**

**また、プロキシについての注意があります。**

> **一部の機能は `bridge.claudeusercontent.com` を経由して接続します**: Claude in Chrome、Cowork、Remote Tools、Office のアドインの「work across apps」。**あなたのプロキシが、そのホストを `claude.ai` と `api.anthropic.com` とは別のアドレスから外に出している場合は、そのアドレスも列挙してください**

## ③ 今日の変更（説明つき）

### 鍵が漏れても、使える場所を限れるようになりました

**IP 許可リストが何のためのものか**を、ドキュメントの説明をそのまま訳します。

> **IP 許可リストは、対象のリクエストが特定の IP の範囲からのみ来ることを許すことで、あなたの組織を守ります。** **これは、API キーが漏れたとしても、攻撃者がそのキーを使うのがずっと難しくなることを意味します。** **データの漏洩を防ぎ、不正な利用で請求される可能性を減らせます。**

**IP アドレス**= インターネット上の住所です。**「この住所から来たリクエストだけを受ける」**という設定になります。

**仕組み**はこうです。

> **組織の管理者またはオーナーが、設定で IP の範囲の一覧を用意します。** **この範囲の一覧は、組織の全体を対象とします。** **対象の各リクエストについて、Anthropic はそのリクエストの公開 IP アドレスをあなたの一覧と照合し、許可されていなければ拒否します。**

**「組織の全体を対象とする」「管理者も同様に遮断される」**という点が、②で書いた「締め出されないように」の注意につながります。

**遮断された人がどうなるか**も書かれています。

> - **他のアカウント**: **遮断された利用者は、依然としてサインインして、他の組織や個人のアカウントを使えます**
> - **リモートの利用者**: **携帯回線の電話、自宅の Wi-Fi、VPN を切ったノートパソコンは、列挙されたネットワークを通じて接続するまで遮断されます**

**「自宅から仕事をしている人が全員止まる」**という形になりうる、ということです。

### 変更の記録が残せることも書かれています

> **組織について Compliance API を設定していれば、その Activity Feed が許可リストへの変更を記録するので、監査できます**

**「戻る道を確保する」チェックボックスには攻撃のリスクがある**とドキュメント自身が認めていて、**その代わりに変更の記録で補う**という組み合わせが示されています。

### リリースノートの過去の項目に、大規模な文言の整理が入りました

**今日のリリースノートには、新規2件のほかに、過去の項目の書き換えが30件以上あります。** **内容が変わったものは1件もありません。** 以下は代表的なものです。

- **「Claude on Google Cloud」→「Claude Models on Google Cloud (Google managed)」**（Claude Haiku 5.5・Sonnet 5.5・Opus 5.5・Fable 5.1・Opus 5 の公開の項目、計5か所）
- **リンクの文言をリンク先の見出しに合わせる修正**（「Fast mode」→「Fast mode model availability」、「Preserved thinking」→「Thinking blocks stay with the account that produced them」、「migration guide」→「Claude Haiku 5.5 migration guide」など）
- **引退・廃止の推奨先のリンクが、比較表ではなく各モデルのページへ**（Claude Opus 4.1 → `models/opus-5/overview`、Claude Opus 4.8 → `models/opus-4-8/overview` が3か所）

- **ダッシュで繋いでいた文を、コロンやカンマに**（「no action needed」「matching the citation quality」など）
- **「You can now put words in Claude's mouth when using tools.」→「You can now prefill Claude's response when using tools.」**（**比喩をやめて、直接的な表現に**）
