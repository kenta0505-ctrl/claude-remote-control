## ② ⚠️ 今の使い方が変わるもの

### 1. 「止めるはずの操作がすり抜けていた」穴が5件直りました

**今日いちばん重い塊です。** 以下はすべて 2.1.319 の修正です。**今まで通っていた操作が、今日から止まります。**

> - **worktree を作るときのサンドボックスの脱出**を修正
> - **細工された環境変数の接頭辞が、コマンドの一部を権限チェックから隠せた Bash の権限の迂回**を修正
> - **accept-edits モードと auto モードで、`sed` のコマンドが権限チェックを飛ばせた場合**を修正
> - **`/rewind` が、ディレクトリのシンボリックリンク（別名の入口）を通じてファイルを復元または削除しえた場合**を修正
> - **claude.ai のコネクタの端末上の名前（`mcp__claude_ai_Slack` など）で書かれた拒否・確認のルール、フックの照合、`disallowedTools` の項目が、Claude Desktop で無視されていた場合**を修正（**Claude Desktop がこのバージョンを含んだ時点で有効になります**）

**「サンドボックスの脱出」**は、**隔離された場所で動かしているはずのコマンドが、外に出られた**ということです。**「Bash の権限の迂回」**は、**コマンドの一部を隠すことで、確認を通さずに実行できた**ということです。

**worktree と sandbox について、さらに2件の変更があります。**

> - **入れ子のスキルの読み込みを変更**: **Bash のサンドボックスがオンのとき、開始フォルダより下の `.claude/skills` フォルダのスキルは、そこで Claude Code を起動した場合か `/cd` でそこに移った場合にだけ読み込まれます**
> - **自前ランナーを修正**: **`--trust-workspace false` が、リポジトリの設定ファイルの中のフックとスキルの実行も止めるようになりました**

**2つ目は特に重要です。** **「このワークスペースを信頼しない」と指定しても、リポジトリの中のフックとスキルは動いていた**ということです。

**あわせて、止める側のルールの扱いが5件変わりました。**

> - **Monitor の WebSocket の監視**を、**すべての Bash のコマンドについてルールに従うよう変更**: **拒否ルールはそれを拒否し、確認ルールの下では、Monitor への許可・bypass モード・auto モードが確認を飛ばさなくなりました**
> - **`CLAUDE_CODE_PROXY_RESOLVES_HOSTS`** を、**ホストがネットワークを管理している場所では、設定ファイルから設定できないよう変更。** プロセスの環境で設定してください
> - **セッションの厳密な Bash または PowerShell の確認ルール**を、**より広い拒否ルールがそのコマンドを覆っているときに、確認するのではなく拒否するよう変更**
> - **Bash ツール**を、**参照・表示の範囲の外のフラグを付けた `which` を実行する前に、権限を求めるよう変更**
> - **`--add-dir` のディレクトリ**を、**そのディレクトリ自身の信頼のダイアログが受け入れられた後にだけ、プラグインのマーケットプレイスを登録するよう変更**

**引用符を使った迂回の修正も1件あります。**

> **Bash の拒否と確認のルールが、引用符で囲まれた語で書かれたコマンドを見逃していた場合**を修正

### 2. auto モードの挙動が、動作記録をオフにしている環境で変わりました

> **動作記録（telemetry）や機能フラグをオフにしている場合の auto モードを変更**（**LLM ゲートウェイの背後も含む**）: **サーバーが確認できない呼び出しは、確認を求められるか拒否されます。** **組み込みの判定器へのフォールバックはありません。** **引き続き使うには `CLAUDE_CODE_AUTO_MODE_SERVER=0` を設定してください**（**Bedrock・Vertex・Foundry は変わりません**）

**これまでは、サーバーに判定を聞けないとき、Claude Code の中の判定器が代わりに判断していました。** **今日から、それがなくなります。** **判定できなければ確認を求めるか拒否する**という、より厳しい側に寄りました。

**関連して、auto モードについて6件の変更・修正があります。**

> - **LLM ゲートウェイの背後の auto モードを変更**: **`CLAUDE_CODE_AUTO_MODE_SERVER=1` が、`CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` が設定されていてもサーバー側のチェックをオンにします。** **管理された設定が後者を設定している場合は、`1` も設定する必要があります**
> - **auto モード**を、**プロジェクトの外でサーバー側のチェックをオフにした後は、プロジェクトの設定ファイルやプラグインがそれをオンに戻せないよう変更**
> - **ベース URL として設定された LLM ゲートウェイが 403 または 422 を返すときに、auto モードが毎ターン失敗していた場合**を修正（**昨日も同系統の修正がありました**）
> - **`/status` が「Auto mode server: Enabled」と表示していた場合**を修正（**サーバー側のレビューがそのセッションに届いていないとき、たとえばそれを落とす LLM ゲートウェイの背後など**）
> - **権限ルールや `autoMode` の設定が非常に大きいときに、auto モードが理由を言わずに操作を拒否していた**のを修正。**今後は説明し、`autoMode` の拒否ルールが設定されていない限り、端末で確認を求めます**
> - **安全性チェックが利用できなかったために操作が拒否されたとき、auto モードの `claude -p` が 0 で終了していた**のを修正。**テキストと JSON の出力は 1 で終了します**

**最後の1件は、昨日の「ディスク満杯で 0 終了」の修正と同じ形**です。**失敗を成功として報告していた**ものが続けて直っています。

### 3. 権限の確認を待たずに拒否して進む設定が追加されました

> **`permissions.denyInsteadOfPrompting` の設定を追加**: **権限の確認を待つことになるツール呼び出しが拒否され、ターンが続きます。** **端末のセッション、サブエージェント、同僚で有効です**

**無人で動かしているときに、確認で止まらずに「拒否して先に進む」**という選択肢ができました。

## ③ 今日の変更（説明つき）

### `/clear` が、動き続けるはずのものを止めていた不具合が直りました

> **`/clear` が、動き続けるバックグラウンドのエージェント・同僚・ワークフローの実行中のコマンドを、またバックグラウンドのエージェントと同僚のフォアグラウンドのサブエージェントを、終了させていた**のを修正

`/clear` = 会話をまっさらにするコマンドです。**「会話を消すだけ」のつもりが、裏で動いている作業も止めていた**ということです。

**関連して、クラウドセッションでも同じ形の修正があります。**

> **[Cloud sessions] クラウドセッションで、待っているメッセージの「Send now」が、実行中のバックグラウンドのエージェントを終了させていた**のを修正。**今後は動き続けます**

### フォルダに `HEAD` という名前のファイルがあると、差分が壊れる不具合が直りました

> - **Claude Code が動いているフォルダに `HEAD` という名前のファイルまたはフォルダがあるときに、セッションの差分が claude.ai とモバイルアプリで読み込めなかった**のを修正
> - **git リポジトリの最上位に `HEAD` という名前のファイルまたはフォルダがあるときに、`/diff` が「Diff unavailable」と表示していた**のを修正

**`HEAD` は git が内部で使う名前**です。**同じ名前のファイルが普通に置かれていると、git の内部のものと混同されていた**ということです。

### 設定ファイルが空になる不具合が、さらに直りました

> **読み取り専用のフォルダへの保存中、またはバインドマウントされたファイルへの保存中にディスクが満杯になったときに、`~/.claude.json`・設定・編集したファイルが空になったり途中で切れたりしていた**のを修正（**一度に保存するのは1セッション**）

> **設定が旧来の名前のまま残っていると、警告なしにあなたの設定が隠れていた**のを修正。**ホームに2つの設定ファイルがある場合、Claude Code は標準エラー出力でそう言い、どちらが使われているかを示すようになりました**

> **Windows での設定の保存を改善**: **別のプログラムが開いているファイルを、Claude Code がより長く待つようになりました。** **保存中の強制終了で `~/.claude.json` が空になる可能性が減ります**

**昨日（11月5日分）も設定ファイル関連の修正が6件ありました。** **2日続けて同じ領域が直っています。**

### Claude のログインが切れたときに、別の組織に請求される可能性が示されました

> - **claude.ai のログインが終わり、Claude Code が `ant auth login` のサインインで続行するときの警告を追加。** **これは使用量をあなたの Claude Console の組織に請求します**
> - **Claude Code が `ant auth login` のサインインを使う場合に、請求される Claude Console の組織の名前を挙げる行を、起動時に追加**

**「気づかないうちに別のアカウントに請求されていた」**可能性があった、ということです。**今日から、どの組織に請求されるかが起動時に表示されます。**
