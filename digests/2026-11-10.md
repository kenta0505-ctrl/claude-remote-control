**原さんへの関係**: **原さんの環境は auto モードです。** ただし**これは Claude Code（ターミナルやクラウドのセッション）の話**で、claude.ai やアプリの会話には mod はありません。

### 3. Claude Code 2.1.321: 「止めるはずの操作がすり抜けていた」穴が4件、秘密情報の漏れが1件、直りました

**ここは安全に直接関わるので、原文をそのまま引きます。**

> - **MCP の OAuth のリクエストが、サーバーにリダイレクトされたときに refresh token などの秘密情報を別のホストに送っていた不具合を修正**
> - **読み取り専用の Bash コマンドが、確認を出さずにサンドボックスの外で実行されていた場合を修正**
> - **Bash の権限確認が、ファイルの書き込みを間違ったフォルダで判定して、確認を出さなかった場合を修正**
> - **`cp` や `mv` でディレクトリに書き込まれるファイルに、拒否ルールと保護ファイルの確認が適用されていなかった不具合を修正**
> - **`/bin/cp` のようにパスで書いた `cp` と `mv` も、`cp` と `mv` と同じパスの確認を受けるよう変更**

**用語を一言で**:

- **「MCP」**: **Claude に外部のサービス（原さんの環境では Square・Gmail・Google Drive・Google カレンダー）をつなぐ仕組み**です
- **「OAuth」**: **パスワードを渡さずにサービスへのアクセスを許可する仕組み**です
- **「refresh token」**: **その許可を更新し続けるための鍵**です。**これが他のサーバーに渡ると、そのサーバーが代わりにアクセスできてしまいます**
- **「サンドボックス」**: **コマンドを隔離された箱の中で動かして、外のファイルを触らせない仕組み**です

**何が起きていたか**: **1件目は、つないだサービスの鍵が、別のサーバーに送られてしまう可能性があった**ということです。**2〜5件目は、本来なら「これを実行していいですか」と聞くか拒否するはずの操作が、聞かれずに通っていた**ということです。

**CHANGELOG には、実際に悪用された事例があったかどうかは書かれていません。** 書いていないので**推測はしません。**

**原さんへの関係**: 原さんは **Square・Gmail・Google Drive・Google カレンダーを MCP でつないでいます。** **1件目はその鍵に関わる種類の不具合**です。**このダイジェストを作っているセッションも Claude Code なので、更新されたバージョンで動くようになります。**

**なお、同じ系統の修正が3週間続いています**（10/22 の 2.1.307、10/28 の 2.1.312、11/7 の 2.1.319、そして今日）。**毎回「すり抜けていた経路」が別です。**

**権限・安全に関わるもの**

- **Claude Code を組み込んだアプリが、別のフックの確認理由ではなく自分のフックの理由を受け取っていた**不具合を修正
- **`PreToolUse` フックの「確認する」が、別のフックの「後回し」が先に終わって守れなかったときに失われていた**不具合を修正

- **その乗っ取りが宣言されていない配布元から来た場合**: 保存データは `cleanupPeriodDays` のあいだ、設定と秘密情報は `claude plugin restore-set-aside` まで取り置かれます
