## ③ 今日の変更（説明つき）

### 1. 昨日 404 だった「Code Mode」のドキュメントが公開されました。中身をまとめます

**昨日、「CHANGELOG が案内する `https://code.claude.com/docs/en/code-mode` が 404 を返す」と報告しました。** **今日、このページは HTTP 200 で返り、Claude Code のドキュメント目次にも載りました。**

> **Run tool calls from code with Code Mode（コードから道具の呼び出しを実行する — Code Mode）** — **Code Mode を試す。Claude が、1ステップで複数の道具の呼び出しをする JavaScript を書く、実験的な機能です**

**ページを読んだので、中身を説明します。すべてこのページに書かれていることです。**

#### どういう仕組みか

> **Code Mode なしの場合**: Claude は Bash・Read・Edit などの道具の呼び出しを**直接**求め、**1つずつ結果を読んでから**次をどうするか決めます
> **Code Mode の場合**: Claude が**道具の呼び出しをする JavaScript を書き**、Claude Code が**あなたのセッションの中でそのコードを実行します**

> **1つのコードで、コマンドを並行して実行し、ある結果を次の呼び出しに使い、Claude が読む必要のある部分だけを返せます**

**ドキュメントに載っている例**（「再試行の上限を上げて」と頼んだ場合に Claude が書くコード）:

```javascript
const files = await $`rg -l "function retryPolicy" src`.text();
const target = files.trim().split("\n")[0];
await edit(target, "maxAttempts: 3", "maxAttempts: 5");
({ edited: target, tests: $`npm test -- retryPolicy`.nothrow() });
```

**この4行で「ファイルを探す → 編集する → テストを走らせる → ファイルのパスとテスト結果を返す」をまとめてやります。**

> **会話の画面には、道具の呼び出し（編集の差分など）が見え、コードは見えません。** **コードを読むには `Ctrl+O` を押して記録の表示を開きます。** **各コードは折りたたまれた「Code」の行として出ていて、広げ方のヒントが付いています**

#### 向いている作業（ドキュメントの記述）

> - **多くのファイルにまたがって繰り返す変更**
> - **Claude が読む前に結果を絞り込む必要がある検索**
> - **同時に実行できる、互いに独立した複数のコマンド**

#### 制限（ドキュメントが「オンにする前に受け入れられるか確認してください」として挙げているもの）

> - **再開**: **Code Mode のセッションは、ターミナルで Code Mode をオンにした状態でしか再開できません**
> - **auto モード**: **auto モードの判定は、道具の呼び出し1つずつではなく「コード」を見ます**
> - **長く動くコード**: **バックグラウンドで動かせない限り、終わるまで待つことになり、10分で止まります**
> - **フック**: **`PreToolUse` フックが実行できないかタイムアウトすると、道具の呼び出しが拒否されることがあります。** `UserPromptSubmit` フックによってコードの出力が止められることもあります
> - **使えない機能**: **Remote Control、Claude in Chrome、コンピュータ操作は使えません**
> - **セッションの移動**: **デスクトップアプリに移したり、バックグラウンドのセッションにしたりできません。** `/fork` でバックグラウンドの複製を始めることもできません

#### 使える条件（ドキュメントの記述）

> - **バージョン**: **Claude Code v2.1.323 以降**（**昨日のバージョンです**）
> - **アカウント**: **Claude のサブスクリプション、または Console のアカウント。** **ゲートウェイ経由、Amazon Bedrock、Claude Platform on AWS、Google Cloud の Agent Platform、Microsoft Foundry 経由では使えません**
> - **組織**: **HIPAA 構成とゼロデータ保持（ZDR）を使っている組織では使えません**
> - **モデル**: **Claude Opus 5.5、Sonnet 5.5、Haiku 5.5、Fable 5.2**
> - **使う場所**: **ターミナルの対話的な `claude` セッション。** **`-p`、Agent SDK、VS Code のパネル、デスクトップアプリ、クラウドセッションでは動きません**
> - **インストール**: **ネイティブ版の Claude Code**
> - **Windows**: **Git for Windows が入っていること**

> **また、API キーのヘルパー、エージェントのチーム、OpenTelemetry のエクスポート、`DISABLE_TELEMETRY` など、一部の設定がオンだと Code Mode を開始できません**

**ここで記録しておくこと**: **原さんの使用モデルは Claude Opus 5 です。** **上の「使えるモデル」の一覧に Opus 5 は入っていません**（入っているのは Opus 5.5、Sonnet 5.5、Haiku 5.5、Fable 5.2）。**また、このダイジェストを作っているセッションはクラウドセッションなので、そこでも使えません。**

#### オンにする方法（ドキュメントの記述）

> **環境変数 `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE` を `1` に設定します。** 試すだけならシェルで設定、毎回オンにするならユーザー設定に書きます

```bash
CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1 claude
```

> **Claude Code は、プロジェクトの設定ファイルの中のこの変数を無視します。** **そのため、クローンしてきたリポジトリが、あなたのために Code Mode をオンにすることはできません**

> **最初の Code Mode のセッションの前に、Claude Code が確認を求めます。** 「**Yes, turn on Code Mode**」を選ぶと、Claude Code が再起動して、セッションの上のほうにこの行が出ます: **「Code Mode (experimental) is on · this session can be resumed only with Code Mode on」**

#### オフにする方法 / 組織で止める方法

> **オフにする**: シェルと `~/.claude/settings.json` から変数を外して、新しいセッションを始めます。**変数を残して値を `0` にしてもよいです。** **どちらか一方に `0` があれば、もう一方に `1` があっても Code Mode はオフのままです**

> **組織で止める**: **管理設定に `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE` の値 `0` を追加すると、組織の誰も Code Mode を使えなくなります。** **すでに Code Mode のセッションにいる人は、終了か再起動までそのまま**です。**管理設定から、利用者の Code Mode をオンにすることはできません**

#### 権限はどう確認されるか（ここが一番大事な部分です）

> **Claude のコードがする道具の呼び出しは、1つずつ、あなたの `deny`（拒否）・`ask`（確認）の権限ルールと `PreToolUse` フックを通ります。** **Bash のような道具のために、ルールや一致条件を変える必要はありません**

> - **auto モード**: **判定するものは、コードが実行される前に「コード全体」を見ます。道具の呼び出し1つずつではありません。** **実行時に計算される値（検索結果から取ったパスなど）は見えないので、絶対に制御したい呼び出しには、ルールかフックを残してください**
> - **その他の権限モード**: **コードは審査なしで始まり、そのモードで本来確認が出る道具の呼び出しごとに、あなたに確認が出ます**

> **コード自体を確認したい場合は、`REPL`（Claude のコードを実行する道具）に一致する `PreToolUse` フックを書いて、`tool_input.code` から JavaScript を読んでください**

**ドキュメント自身が付けている警告**:

> ⚠️ **Bash のルールはコマンドの文字列に一致するので、Code Mode があってもなくても、Claude は拒否されたコマンドを、そのルールに一致しない書き方で実行できます。** **コマンドの文字列に依存しない制限が必要なら、サンドボックスを見てください**

#### 長く動くコード

> - **待つ場合**: **Claude はコードが終わってから答えます。** **コードは10分で止まります**（**あなたが権限確認の画面で考えている時間も含みます**）
> - **バックグラウンドの場合**: **Claude と話し続けられ、コードは最大2時間動けます**

> **バックグラウンドで動かすには、auto モードか `bypassPermissions` モードでセッションを始めてください**

**原さんへの関係**: **自分でオンにしない限り、何も変わりません。** **そして上に書いたとおり、原さんの使用モデル（Opus 5）は対応モデルの一覧に入っていません。**

### 2. サブエージェントのモデルの扱いが2件直りました

**何が起きていたか**: **会話がいっぱいになったときに、要約して続ける代わりに、毎回エラーで止まっていた**ということです。

### 4. 予定実行とスキルの確認（②の3番の続き。もう少し詳しく）

**②に書いた変更には、もう1つセットの項目があります。**

**何が変わるか**: **これまでは「常に許可」を押すと、ルールが保存されて次からは通っていました。** **ところが、「ルールを保存しても次は通らない」種類のコマンドもあります**（②の7番に出てきた「`.git` や `.claude` に書き込むコマンド」のような場合です）。

**「スクラッチパッド」とは**: **作業用の一時フォルダ**です。

**何が変わるか**: **Claude が「これは残しておくべきファイル」と「使い捨てのファイル」を区別して、残すべきものは消えない場所に置くようになりました。**

**記録しておくこと**: **この変更は、今日このセッションが受け取った環境の説明にも、実際に現れています**（「再起動や定期的な掃除で消えることがあるので、原さんが残したいものは別の場所に」という文が、今日から入っています）。**つまり、Claude Code の変更が、このセッションの動き方にその日のうちに反映されています。**
