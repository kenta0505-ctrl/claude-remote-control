# 新しいサービスを自動化する前の調査プロンプト

自動化したいサービス（管理画面・SaaS・社内システム）が増えたときに、
**設計の前に必ず1回だけ**走らせる調査。Chrome の Cowork サイドパネルで、
対象サービスにログインした状態で使う。

人間が口頭で説明するより速く、抜けが出ない。特に「CSVエクスポートがあるか」は
設計を根本から変えるのに、意外と見落とされる。

## 使い方

1. 対象サービスにログインし、レポートの元データがある画面を開く
2. Chrome サイドパネルで Claude を開く
3. 下のプロンプトを貼る
4. 出てきた調査結果を、設計する相手（人でもClaudeでも）に渡す

## プロンプト（ここから下をコピー）

```
このサービスの自動化を設計したいので、画面を調査してレポートを作ってください。

【重要な制約】
- 読み取りのみ。ボタンのクリック・フォーム送信・設定変更・ダウンロードは一切しないこと
- メニューを開いて確認するだけならOK。状態が変わる操作は禁止
- 顧客名・メールアドレス・電話番号・金額などの実データは報告に含めないこと。
  「顧客名（例: ○○様）」のように項目名だけを書く

【調べて報告してほしいこと】

1. 基本
   - サービスの正式名称とドメイン
   - ログイン方式（ID/パスワード / Google / SSO）
   - 2段階認証があるか。あるなら毎回聞かれるか、記憶されるか

2. データのある画面
   - レポートの元になる数字がある画面のURL
   - その画面にどんな数字が並んでいるか（項目名だけを列挙）
   - 期間の指定方法（日付ピッカー / プルダウン / URLパラメータ）
   - 絞り込み・フィルタの種類

3. エクスポート機能 ★最重要
   - CSV / Excel / PDF のダウンロードボタンがあるか
   - あるなら、どの画面のどこにあり、何の単位で出力されるか
   - 無いなら「無い」と明記すること

4. 連携機能
   - 「API」「連携」「Webhook」「外部サービス」といったメニューが設定内にあるか
   - あれば、そのページに何が書いてあるか

5. 画面の作り
   - 数字はページを開いた直後に表示されるか、読み込み待ちがあるか
   - 一覧はページ送りされるか（何件ずつか）
   - 表示に何秒くらいかかるか

最後に、調べていて気づいた「自動化の障害になりそうなこと」を挙げてください。
```

## 調査結果の読み方

| 分かったこと | 設計への影響 |
| --- | --- |
| **CSVエクスポートがある** | ブラウザ操作は「DLボタンを押す」だけで済む。集計と作文はファイル側でやる＝速く正確 |
| **CSVエクスポートが無い** | 画面から数字を読み取る。件数が多いと不安定になるので、期間を区切って回数を分ける |
| **APIメニューがある** | 最優先で検討。ブラウザ操作が不要になる可能性がある |
| **2段階認証が毎回required** | 無人の定期実行は不可。人が起動する運用にする |
| **ページ送りがある** | 「全ページ取得」を手順に明記しないと1ページ目だけで完了扱いになる |
| **読み込み待ちがある** | 「数字が表示されるまで待つ」を手順に入れる。待たないと空データを掴む |
